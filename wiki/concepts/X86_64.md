# x86-64

**x86-64** (also called **AMD64** or **Intel 64**) is the **64-bit extension of the [[IA32|32-bit x86]] [[ISA]]** — the dominant desktop, laptop, and server architecture from the mid-2000s onward. Originated by AMD (2000, Opteron) and adopted by Intel; binary-compatible with [[IA32]] in legacy mode, byte-compatible at the instruction-encoding level. The default target of `gcc` / `clang` on modern Linux and macOS. *Promoted from forward-reference to first-class [[ISA]] page by [[dis-7-1-x86-64-basics|Ch 7.1]].*

## Register set ([[dis-7-1-x86-64-basics|Ch 7.1]])

**16 [[GeneralPurposeRegister|general-purpose 64-bit registers]]** for integer / pointer data:

- `%rax`, `%rbx`, `%rcx`, `%rdx` — legacy A/B/C/D registers, widened to 64 bits.
- `%rdi`, `%rsi` — destination / source index, widened.
- `%r8`, `%r9`, `%r10`, `%r11`, `%r12`, `%r13`, `%r14`, `%r15` — **eight new registers** beyond the original [[IA32]] eight.

**Three special-purpose registers** ([[dis-7-1-x86-64-basics|Ch 7.1]]):

- **`%rsp`** — stack pointer (reserved by the compiler; top of the stack).
- **`%rbp`** — frame / base pointer (reserved by the compiler; bottom of the current [[StackFrame|frame]] when frame pointers are enabled).
- **`%rip`** — instruction pointer / program counter; **read-only — cannot be written directly** by ordinary `mov` instructions. (The [[InstructionPointer]] is updated implicitly by control-flow instructions.)

Plus `%eflags` (condition-code register, surfaced by [[GdbInfo|`info registers`]] in [[dis-3-5-gdb-assembly|Ch 3.5]]).

## Subregister naming ([[dis-7-1-x86-64-basics|Ch 7.1]])

Each 64-bit register exposes its lower 32 / 16 / 8 bits under distinct names — letting one instruction operate on whichever width matches the [[CPrimitiveType|C type]]:

| 64-bit | 32-bit | 16-bit | 8-bit (low) | 8-bit (high) |
|---|---|---|---|---|
| `%rax` | `%eax` | `%ax` | `%al` | `%ah` |
| `%rbx` | `%ebx` | `%bx` | `%bl` | `%bh` |
| `%rcx` | `%ecx` | `%cx` | `%cl` | `%ch` |
| `%rdx` | `%edx` | `%dx` | `%dl` | `%dh` |
| `%rdi` | `%edi` | `%di` | `%dil` | — |
| `%rsi` | `%esi` | `%si` | `%sil` | — |
| `%rsp` | `%esp` | `%sp` | `%spl` | — |
| `%rbp` | `%ebp` | `%bp` | `%bpl` | — |
| `%r8` | `%r8d` | `%r8w` | `%r8b` | — |
| ... | ... | ... | ... | — |
| `%r15` | `%r15d` | `%r15w` | `%r15b` | — |

Two distinct rules: the **letter-substitution** scheme for the original eight registers (replace `r` with `e` for 32 bits; drop the prefix for 16 bits; use the `l`/`h` low/high-byte name for the original four A/B/C/D registers) and the **suffix** scheme for the new `%r8`–`%r15` (append `d` / `w` / `b`).

The [[CCompiler|compiler]]'s rule per [[dis-7-1-x86-64-basics|Ch 7.1]]: *"The compiler typically uses the 64-bit registers when dealing with 64-bit values (e.g., pointers or long types) and the 32-bit component registers when dealing with 32-bit types (e.g., int)."*

## Calling convention (System V) — first six args in registers

Per [[dis-7-1-x86-64-basics|Ch 7.1]]: *"Compilers typically store the first six parameters in registers `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8` and `%r9`, respectively. Register `%rax` stores the return value from a function."* Subsequent arguments spill to the stack. This is the **System V AMD64 ABI** used on Linux and macOS — a major departure from [[IA32]]'s stack-only argument passing.

## Instruction format — [[AtAndTSyntax|AT&T syntax]] on Linux

Default syntax in [[GCC|`gcc`]] / [[GDB]] / [[Objdump|`objdump`]]:

- **Opcode + operands**, with **source first, destination second** — `mov src, dst`.
- Registers prefixed `%`; immediates prefixed `$`.
- Memory operands: `disp(base, index, scale)`.
- Per-instruction [[OperandSize|size suffix]] (`b` / `w` / `l` / `q`) selects the data width.

The competing [[IntelSyntax|Intel syntax]] (`mov dst, src`, no prefixes, `[base + index*scale + disp]`) is used by Microsoft tools and the official Intel reference manuals.

## CISC characteristics

x86-64 is **CISC** — variable-length instructions (1 to 15 bytes), rich addressing modes (`disp(base, index, scale)` with scale ∈ {1,2,4,8}), memory operands available to most arithmetic instructions, and a large opcode space accumulated over four decades of backward compatibility. Internally, modern x86-64 CPUs decode CISC instructions into RISC-like **µops** for [[Superscalar|superscalar]] out-of-order execution — the [[ISA]] is CISC but the microarchitecture is RISC-flavored.
