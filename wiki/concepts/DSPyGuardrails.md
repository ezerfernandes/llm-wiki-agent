# DSPy Guardrails

**DSPy Guardrails** is a method for building [[Guardrail|LLM safety guardrails]] as **automatically-optimized [[DSPy]] programs** rather than hand-written rules or prompts. Introduced by [[BoxiYu]] & [[PinjiaHe]] ([[CUHKShenzhen]]) in *DSPy Guardrails: Building Safe LLM Applications via Self-Refining Language Model Pipelines* ([[dspy-guardrails|paper, 2024]]).

## The two-step recipe

1. **Define the LLM Program with guardrails** using a [[DSPySignatures|DSPy signature]] whose inputs include the user `text` *and* a `guardrails` description, and whose output is the assistant `answer`. Wrap with a [[DSPyModules|`dspy.Module`]] over [[ChainOfThought|`dspy.ChainOfThought`]].
2. **Provide datasets** of jailbreak / benign prompts and **select a [[DSPyOptimizers|DSPy optimizer]]** (the paper uses [[BootstrapFewShot]]) to automatically optimize instructions and few-shot demonstrations.

The optimizer is the load-bearing piece: on [[CodeAttack]] against gpt-3.5-turbo-instruct, the unoptimized DSPy program reaches **30% [[AttackSuccessRate|ASR]]**, while the optimized version reaches **5%** — vs. **75%** for the 8-shot in-context-learning baseline.

## Signature shape (Listing 1)

```python
class Assistant(dspy.Signature):
    text = dspy.InputField(desc="Instructions to the assistant")
    guardrails = dspy.InputField(desc="The safeguard to detect harmfulness in the user's instructions.")
    answer = dspy.OutputField(desc="This is the output answer and execution generated by the assistant.")
```

The **guardrail itself is an input field**, not a separate module. This is the structural decision that lets [[DSPyOptimizers|the optimizer]] tune the guardrail description as part of the prompt-search.

## Position vs. other guardrails

| Guardrail | Source of safety rules | Adapts to new attacks |
|---|---|---|
| [[LlamaGuard]] | Trained classifier over a fixed safety taxonomy | Retrain |
| [[NeMoGuardrails]] | Human-written [[Colang]] dialog flows | Edit Colang |
| [[GuardrailsAI]] | Human-written validators / output specs | Edit validators |
| **DSPy Guardrails** | **Auto-optimized prompt + few-shot demos** | **Re-run [[BootstrapFewShot]] with new examples** |

The methodological claim: *"jailbreak techniques are constantly evolving every day"* (paper), so the human-rule layer becomes the bottleneck — replace it with an automatic optimizer over an annotated dataset.

## Caveats

- Evaluated against **one attack** ([[CodeAttack]]), **one model** (gpt-3.5-turbo-instruct), **20 prompts**. Does not benchmark against [[LlamaGuard]] / [[NeMoGuardrails]] / [[GuardrailsAI]] head-to-head.
- Most of the gain comes from `BootstrapFewShot` demonstration search, not from DSPy's abstraction per se — a stronger optimizer ([[2406.11695-mipro|MIPRO]], [[2507.19457-gepa|GEPA]]) is the natural successor here.
- The defender shares model family with the attack distribution — generalization to attacks crafted *after* the bootstrap dataset is not tested.
