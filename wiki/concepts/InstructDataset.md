## Definition
An **instruct dataset** (or instruction dataset) is a collection of `(instruction, response)` pairs — optionally including a system prompt and chat-turn structure — used to fine-tune a Large Language Model for instruction-following. It is the canonical input format for [[SupervisedFinetuning|Supervised Fine-Tuning]] (SFT).

## In LLM Engineer's Handbook
[[leh-ch01-understanding-llm-twin-concept]] introduces the instruct dataset as the artifact the feature pipeline emits for the training pipeline to consume — versioned in the [[FeatureStore]] and re-derivable from the [[DataWarehouse]]. [[leh-ch05-supervised-fine-tuning]] is the long-form treatment: the authors argue that **building the instruction dataset is the hardest part of fine-tuning** (not training itself). They enumerate three quality dimensions (accuracy, diversity, complexity), quantity heuristics by model scale (~1,000 high-quality pairs may suffice for a 70B model per the LIMA paper; ~1M+ for general-purpose 7B; 100–100,000 for task-specific), storage formats (Alpaca, ShareGPT, OpenAI, OASST, raw text), and a full toolkit for curation: rule-based filtering, exact/fuzzy/semantic deduplication, decontamination against eval sets, LLM-as-a-judge quality scoring, reward-model scoring, classifier filters, and synthetic generation via Evol-Instruct / UltraFeedback / backtranslation. The book's concrete example is `mlabonne/llmtwin` — 3,335 instruction-answer pairs generated by GPT-4o-mini from author articles for <$0.50.

## Key details
- Three quality axes: **accuracy** (correctness), **diversity** (broad task coverage), **complexity** (challenge).
- Standard storage formats: Alpaca, ShareGPT, OpenAI chat-format, OASST, raw text (the last is "continual pre-training").
- Distinguished from a *preference* dataset (used in [[DirectPreferenceOptimization|DPO]]): an instruct dataset has one response per instruction; a preference dataset has a chosen + rejected pair.
- Sample-count rules of thumb: 1K (LIMA, 70B), 1M+ (general 7B fine-tunes), 100–100K (task-specific), millions (frontier post-training).
- Quality interventions: MinHash fuzzy dedup, semantic dedup (sentence-transformer embeddings + cosine + DBSCAN/K-means), `fineweb-edu-classifier`, [[LLMAsAJudge]] with multi-judge jury.

## From [[ai-engineering-ch08-dataset-engineering|AI Engineering Ch 8]]

Ch 8 is the wiki's most detailed treatment of how instruct datasets are *synthesized at scale*. Key Ch 8 contributions:

### The three-dimensional quality framework

Where LEH's three axes are **accuracy / diversity / complexity**, Ch 8's six **[[DataQuality|quality characteristics]]** generalize: *relevant, aligned with task requirements, consistent, correctly formatted, sufficiently unique, compliant*.

### Canonical synthetic instruct datasets (Ch 8)

- [[AlpacaDataset|Alpaca]] — 175 [[SelfInstruct]] seeds → 52K via text-davinci-003.
- [[UltraChat]] — ChatGPT topic-tree, multi-turn.
- [[MetaMath]] — 15K → 400K via paraphrasing of MATH + GSM-8K.
- [[Cosmopedia]] — 25B-token synthetic textbook corpus (Mixtral-8x7B).

### The synthesis taxonomy

Ch 8 splits instruction-data synthesis by which side is AI-generated:

- AI generates instructions + AI responses (Alpaca, Cosmopedia).
- AI instructions + human responses ([[ReverseInstruction|reverse instruction]] variants).
- Human instructions + AI responses (response-augmentation pattern).

### Multi-turn vs single-turn

Single-turn data is easier to obtain; multi-turn requires purpose-built scenarios. [[UltraChat]] is Ch 8's example of AI-scaled multi-turn synthesis.
