# Coding Agent

The **Coding Agent** pattern (a.k.a. the human-augmented coding team) is the production-oriented framework presented in [[agentic-design-patterns-appendices-bg|*Agentic Design Patterns* Appendix G]] (Gulli) for organizing a **human-led team of specialized AI coding agents**. Its core philosophy: human developers act as creative leads and architects, while AI agents function as tireless **force multipliers** for specialized, scalable tasks (testing, documentation, review). It is the structured successor to [[VibeCoding|vibe coding]], which the book treats as ideation/scaffolding only.

The book grounds this in industry signal: in early 2025 Alphabet CEO Sundar Pichai noted **"over 30% of new code is now assisted or generated by [Google's] Gemini models"**, with Microsoft (Satya Nadella) making a similar ~30% claim.

## Three foundational principles
1. **Human-Led Orchestration** — the developer is the team lead/project architect, always in the loop, setting high-level goals and making final decisions; agents are powerful but supportive collaborators.
2. **The Primacy of Context** — an agent's performance depends *entirely* on context quality; automated black-box retrieval is avoided in favor of a meticulous, human-led briefing comprising: **the complete codebase** (existing patterns/logic), **external knowledge** (docs, API definitions, design documents), and **the human brief** (clear goals, requirements, PR descriptions, style guides).
3. **Direct Model Access** — power agents with **frontier models directly** (e.g. [[gemini|Gemini]] 2.5 Pro, [[anthropic|Claude]] Opus 4, [[openai|OpenAI]], DeepSeek); avoid weaker models or intermediary platforms that obscure or truncate context.

## Core components
- **The Orchestrator (the human developer)** — team lead, architect, final decision-maker; defines tasks, prepares context, validates all agent work. Interface: the developer's own terminal/editor + the native web UI of the chosen agents.
- **The Context Staging Area** — a dedicated, task-specific workspace where the developer assembles a complete, accurate briefing. Implemented as a temporary directory (e.g. `task-context/`) of markdown files for goals, code, and relevant docs. This is the foundation for every successful agent interaction.
- **The Specialist Agents** — conceptual personas (not separate apps) invoked inside one frontier LLM via role-specific **invocation prompts**:
  - **Scaffolder / Implementer** — writes new code, features, boilerplate from specs. *("You are a senior software engineer. Based on the requirements in 01_BRIEF.md and the existing patterns in 02_CODE/, implement the feature...")*
  - **Test Engineer / Quality Guard** — writes unit, integration, and end-to-end tests. *("You are a quality assurance engineer. For the code provided in 02_CODE/, write a full suite of unit tests using [Testing Framework, e.g., pytest]. Cover all edge cases...")*
  - **Documenter / Scribe** — generates docs for functions, classes, APIs, codebases. *("You are a technical writer. Generate markdown documentation for the API endpoints... Include request/response examples...")*
  - **Optimizer / Refactoring Partner** — proposes performance optimizations and refactors. *("Analyze the provided code for performance bottlenecks or areas that could be refactored for clarity...")*
  - **Process / Code Supervisor** — a reviewer combining **Critique** (an initial static-analysis-like pass for bugs/style/logic flaws) + **[[Reflection|Reflection]]** (synthesize the critique, prioritize critical issues, dismiss low-impact ones, produce a concise actionable summary). *("You are a principal engineer conducting a code review. First, perform a detailed critique of the changes. Second, reflect on your critique to provide a concise, prioritized summary...")*

## Practical implementation (setup checklist)
1. **Provision access to ≥2 frontier models** (e.g. Gemini 2.5 Pro + Claude 4 Opus) for comparative analysis and redundancy.
2. **Implement a local context orchestrator** — a lightweight CLI / local agent runner driven by a `context.toml` config specifying which files/dirs/URLs compile into a single LLM prompt payload (full, transparent control over what the model sees).
3. **Establish a version-controlled prompt library** — a `/prompts` directory storing each specialist's invocation prompt as markdown (`reviewer.md`, `documenter.md`, `tester.md`); **treat prompts as code** so the team can refine and version them.
4. **Integrate agent workflows with Git hooks** — e.g. a pre-commit hook that triggers the Reviewer Agent on staged changes and surfaces its critique-and-reflection summary in the terminal, baking QA into the workflow.

## Principles for leading the team
- **Maintain architectural ownership** — own the "what"/"why"; be the final arbiter of design.
- **Master the art of the brief** — the prompt is a complete briefing package for a highly capable new team member, not a one-line command.
- **Act as the ultimate quality gate** — an agent's output is always a *proposal, never a command*; validate with domain expertise.
- **Engage in iterative dialogue** — refine imperfect output rather than discarding it; the Reviewer's "Reflection" output is meant to start a collaborative discussion.

## Why it matters in agentic systems
The Coding Agent pattern is a concrete instantiation of [[MultiAgentCollaboration|multi-agent collaboration]] + [[Reflection|reflection]] + rigorous **context engineering** for the software-development lifecycle. It reframes the human as orchestrator and quality gate rather than sole contributor, elevating the human role to strategy/architecture while delegating tactical execution. Closely related to the CLI agents profiled in [[agentic-design-patterns-appendices-bg|Appendix E]] ([[claudecode|Claude Code]], [[GeminiCLI|Gemini CLI]], [[Aider]], [[copilotcli|GitHub Copilot CLI]]) and to [[codingagents]].
