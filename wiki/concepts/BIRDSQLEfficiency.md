# BIRD-SQL Efficiency

[[BIRDSQL|BIRD-SQL]]'s **efficiency-aware evaluation criterion** for text-to-SQL. Per [[ai-engineering-ch04-evaluate-ai-systems|*AI Engineering* Ch 4]]:

> "BIRD-SQL (Li et al., 2023) is an example of a benchmark that takes into account not only the generated query's execution accuracy but also its efficiency, which is measured by comparing the runtime of the generated query with the runtime of the ground truth SQL query."

## Why efficiency matters

> "If an SQL query generated by your text-to-SQL model is correct but takes too long or requires too much memory to run, it might not be usable."

Functional correctness is necessary but not sufficient — production SQL must run fast enough to be useful.

## How it's computed

Compare the generated query's runtime to the ground-truth SQL query's runtime on the same database. Slower-than-ground-truth queries score lower even when functionally equivalent.

## Position

The clearest extension of the [[ExactEvaluation|exact-evaluation]] paradigm into a beyond-correctness dimension. Sibling concern: [[CodeReadability|code readability]] in generated code generally.
