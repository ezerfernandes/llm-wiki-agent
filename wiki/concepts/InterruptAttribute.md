# `#[interrupt]` Attribute

The **declarative surface for device-specific [[Interrupt|interrupt]] handlers in Rust** — sibling to [[ExceptionAttribute|`#[exception]`]]. Marks an ordinary `fn` as the handler for a **vendor-named** interrupt the chip's [[NVIC|NVIC]] dispatches (e.g. `TIMER2A`, `USART1`, `EXTI0`).

```rust,ignore
use lm3s6965::interrupt; // Re-exported attribute from the device crate

#[interrupt]
fn TIMER2A() {
    // ..
    // Clear reason for the generated interrupt request
}
```

## Do not use the `cortex-m-rt-macros` attribute directly

The underlying macro lives in `cortex-m-rt-macros` (gated on `cortex-m-rt`'s **`device` feature**), but **using it directly will cause a compilation error** ([[rust-embedded-book-start-interrupts]]). Instead, users must use the **re-exported version from the device crate** — typically `<chip-pac>::interrupt`, e.g.:

```rust,ignore
use lm3s6965::interrupt;
// or
use stm32f1::stm32f103::interrupt;
```

The device crate is itself usually generated by [[Svd2Rust|`svd2rust`]] from the chip's [[SVDFile|CMSIS-SVD]] description. Going through the device-crate re-export means **the compiler can verify the interrupt actually exists on the target device** — `TIMER2A` will compile on an LM3S6965 device crate but fail on an STM32F1 device crate that doesn't expose that name. The list of available interrupts (and their position in the [[VectorTable|interrupt-vector table]]) is auto-generated from the SVD by `svd2rust`.

## Same two non-obvious guarantees as `#[exception]`

The chapter explicitly says the mechanism mirrors [[rust-embedded-book-start-exceptions|exceptions]]:

1. **Software-uncallable**. A `#[interrupt]`-tagged function **cannot be called from regular Rust code** (special hardware calling convention). It is reachable only through the [[NVIC]]'s dispatch path via the [[VectorTable]] — *or* via the NVIC's `STIR` software-trigger register, which deliberately raises an interrupt request in software.
2. **`static mut` inside the body is *safe***. The attribute rewrites every `static mut X: T = …;` in the body into a `&mut T` binding of the same name. Soundness rests on the prior guarantee: because the handler is hardware-dispatched and the [[NVIC]] will not concurrently re-enter the *same* handler on a single core, the `&mut` is unique by construction.

```rust,ignore
#[interrupt]
fn TIMER2A() {
    static mut COUNT: u32 = 0;

    // `COUNT` has type `&mut u32` and it's safe to use
    *COUNT += 1;
}
```

## Handler-shape differences from `#[exception]`

- **Handler name** is *vendor-supplied* (from the device crate's interrupt enum), not architecturally fixed. Whereas `#[exception]` recognizes a closed set of names (`SysTick`, `HardFault`, `NMI`, …), `#[interrupt]` accepts any name the device crate exports.
- **No `DefaultHandler`-like catch-all signature variant**; the catch-all for un-handled device interrupts goes through [[DefaultHandler|`DefaultHandler`]] with `irqn: i16 ≥ 0`.
- **Don't forget to clear the cause**: a `#[interrupt]` body that doesn't clear the peripheral's interrupt-request flag will be re-entered endlessly by the NVIC — see [[NVIC]]'s three "advanced uses".

## Connections

- [[Interrupt]] — the underlying concept; `#[interrupt]` is its Rust attribute surface.
- [[ExceptionAttribute]] — sibling attribute for architectural Cortex-M exceptions; same `static mut`/software-uncallable design recipe.
- [[CortexMRTCrate]] — supplies the underlying `interrupt` macro (gated on the `device` feature) that the device crate re-exports.
- [[Svd2Rust]] — generates the device crate's interrupt enum and `#[interrupt]` re-export from the [[SVDFile|chip's SVD]].
- [[SVDFile]] — the vendor description that fixes interrupt names and vector-table positions per chip.
- [[NVIC]] — the controller that dispatches `#[interrupt]`-tagged handlers; its three advanced-use properties (priority, nesting, clear-reason) shape correct handler code.
- [[VectorTable]] — the data structure `#[interrupt]` ultimately writes into (in the device-specific IRQ slots, `irqn ≥ 0`).
- [[DefaultHandler]] — the catch-all whose `irqn ≥ 0` branch services un-handled device interrupts.
- [[LM3S6965]] — the example device whose `lm3s6965::interrupt` re-export the chapter uses.
