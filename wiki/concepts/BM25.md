## Definition
**BM25** (Best Matching 25) is a probabilistic information-retrieval ranking function that scores a document's relevance to a query as a TF-IDF-style sum, with saturating term-frequency and length-normalized weighting. BM25 is the canonical sparse / keyword-search baseline, complementary to dense vector embeddings.

## In LLM Engineer's Handbook
[[leh-ch09-rag-inference-pipeline]] references BM25 in the chapter's future-improvement section on **hybrid search**: combining the LLM Twin's dense vector retrieval (cosine over sentence-transformer embeddings in [[Qdrant]]) with a BM25 sparse retrieval, then merging via score normalization and a weighted combination. The chapter argues hybrid search compensates for both retrieval failure modes: pure vector search misses exact-keyword matches (the "Java the language vs. Java the island" example), while pure BM25 misses semantically similar but lexically distinct documents.

## Key details
- Sparse retrieval: documents and queries become high-dimensional sparse term-frequency vectors.
- Saturating term frequency (controlled by `k1` hyperparameter, typically ~1.2) prevents stuffing.
- Length normalization (controlled by `b`, typically ~0.75) corrects for document length bias.
- Hybrid search blends BM25 and vector scores with an alpha weight (`alpha=0` pure BM25, `alpha=1` pure vector).
- Commonly available in Elasticsearch, OpenSearch, Lucene, Tantivy, and as a Qdrant/Weaviate option.

## From [[ai-engineering-ch06-rag-agents|AI Engineering Ch 6]]

[[ChipHuyen|Huyen]] devotes substantial Ch 6 attention to BM25 as **the formidable baseline of modern retrieval**. The Okapi BM25 algorithm (Robertson et al. 1980s; *"the 25th generation of the Best Matching algorithm"*) is presented as the modification of [[TFIDF|TF-IDF]] that **normalizes term-frequency scores by document length** — fixing TF-IDF's bias toward long documents (which trivially contain more occurrences of any given term).

The chapter's load-bearing quote comes from [[AravindSrinivas|Aravind Srinivas]] (CEO of [[Perplexity]]) on Twitter:

> *"Making a genuine improvement over BM25 or full-text search is hard."*

This is **why term-based retrieval still matters in the embedding era** — not despite, but because of, modern embeddings. Huyen positions BM25 as part of the [[TermBasedRetrieval]] family (alongside [[Elasticsearch]] and [[Lucene]] implementations) and pairs it with [[EmbeddingBasedRetrieval]] in production [[HybridSearch|hybrid search]] — typically sequential (BM25 fetches candidates, embedding-based reranks) or parallel via [[ReciprocalRankFusion|RRF]].

Variants Huyen names: **BM25+**, **BM25F**. The underlying ranking-function family is the de-facto standard for term-based retrieval in [[Elasticsearch]], [[Lucene]], and modern vector DBs ([[Qdrant]] / [[Weaviate]]) that add BM25 alongside their vector indexes.

## From [[hands-on-llm-ch08-semantic-search-and-rag|*Hands-On LLMs* Ch 8]]

Ch 8 uses BM25 as the **direct comparison baseline** for dense retrieval on the *Interstellar* corpus, via `rank_bm25.BM25Okapi`:

```python
from rank_bm25 import BM25Okapi
from sklearn.feature_extraction import _stop_words
import string

def bm25_tokenizer(text):
    tokenized_doc = []
    for token in text.lower().split():
        token = token.strip(string.punctuation)
        if len(token) > 0 and token not in _stop_words.ENGLISH_STOP_WORDS:
            tokenized_doc.append(token)
    return tokenized_doc

tokenized_corpus = [bm25_tokenizer(passage) for passage in texts]
bm25 = BM25Okapi(tokenized_corpus)
```

The tokenizer is the classical IR pipeline: lowercase + tokenize + strip punctuation + remove [[StopWord|stop words]] (`sklearn.feature_extraction._stop_words.ENGLISH_STOP_WORDS`).

**The canonical failure case Ch 8 demonstrates:** on the *Interstellar* corpus with query *"how precise was the science"*, BM25 picks the **wrong** answer (*"Interstellar is a 2014 epic science fiction film co-written, directed, and produced by Christopher Nolan"* — BM25 score 1.789) at rank 1, because the surface keyword *"science"* overlaps. [[DenseRetrieval|Dense retrieval]] over the same corpus picks the **correct** answer (*"praise from astronomers for scientific accuracy"*).

> *"The first result does not really answer the question despite it sharing the word 'science' with the query."* — Ch 8

This is **the canonical motivating contrast** for [[SemanticSearch|semantic search]] over keyword search in the wiki.

**The MIRACL reranker-on-BM25 lift**: per Ch 8, *"on a multilingual benchmark like [[MIRACL]], a reranker can boost performance from 36.5 to 62.8, measured as nDCG@10"* — BM25 is the implicit first-stage retriever the reranker improves upon, demonstrating that **BM25 plus a [[CrossEncoder|cross-encoder]] reranker rivals or beats end-to-end dense retrieval** at the production level.

The two-stage pipeline pattern Ch 8 codifies: **BM25 first-stage retrieval (top-100 or top-1000) → [[CohereRerank|`co.rerank`]] second-stage reranking (top-3)**. The first stage's job is **recall**; the second stage's job is **precision**.

## From [[dspy-rl-multihop-tutorial|DSPy `rl_multihop` tutorial]] — in-process Python BM25 for DSPy retrieval

[[dspy-rl-multihop-tutorial|The DSPy `rl_multihop` tutorial]] introduces **[[bm25s|`bm25s`]] + [[PyStemmer|`Stemmer`]]** as the lightweight in-process Python BM25 retriever for DSPy retrieval programs. This is the **first wiki receipt of `bm25s`** (distinct from [[hands-on-llm-ch08-semantic-search-and-rag|Ch 8's]] `rank_bm25.BM25Okapi`):

```python
import bm25s, Stemmer
stemmer = Stemmer.Stemmer("english")
corpus_tokens = bm25s.tokenize(corpus, stopwords="en", stemmer=stemmer)
retriever = bm25s.BM25(k1=0.9, b=0.4)
retriever.index(corpus_tokens)
```

The tutorial's parameter choice — **`k1=0.9, b=0.4`** — is **looser** than the canonical defaults (`k1≈1.2, b≈0.75`): smaller `k1` saturates term frequency sooner (less reward for term repetition), smaller `b` reduces length-normalization aggressiveness (long documents get penalized less). The combination is appropriate for a corpus of **uniformly-short Wikipedia abstracts** where length variation is naturally compressed.

The retriever indexes **5M Wikipedia page abstracts** (`wiki.abstracts.2017.tar.gz`, 500 MB compressed) in process memory; query-time `retriever.retrieve(tokens, k=k, n_threads=1)` returns top-`k` document indices and BM25 scores in milliseconds. **First DSPy receipt of a BM25-backed retrieval program** — prior DSPy retrieval receipts ([[dspy-tutorial-rag-as-agent]], [[dspy-custom-module]]) used the [[ColBERTv2]] dense-late-interaction retriever. BM25 is appropriate here because:
1. The metric is **title-recall** (titles appear in the BM25-indexed text), so sparse keyword matching is well-aligned to the reward.
2. The student is a **1.5B Qwen** that benefits from a fast, deterministic retriever — every rollout retrieves multiple times, so retriever latency × rollouts × steps is a load-bearing cost term.
3. In-process indexing avoids the network round-trip a hosted ColBERTv2 introduces.
