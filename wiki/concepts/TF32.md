# TF32 — TensorFloat-32

A 19-bit (not 32-bit!) floating-point format designed by [[NVIDIA]] for **A100 / H100 / H200 / Blackwell tensor cores**. Per [[ai-engineering-ch07-finetuning|*AI Engineering* Ch 7]]:

> "TF32 was designed by NVIDIA for GPUs. Note that usually the number at the end of a format's name signifies how many bits it occupies, but TF32 actually has 19 bits, not 32 bits. I believe it was named so to suggest its functional compatibility with FP32. But honestly, why it's called TF32 and not TF19 keeps me up at night."

(Ch 7 footnote: an ex-coworker at NVIDIA conjectured the name was a marketing choice: *"people might be skeptical of weird formats (19-bit), so naming this format TF32 makes it look more friendly."*)

## Bit allocation

- **Sign**: 1 bit.
- **Range** (exponent): **8 bits** — same as [[FP32]] and [[BF16]].
- **Precision** (mantissa): **10 bits** — same as [[FP16]].

Total: **19 bits**, despite the "32" in the name.

## What makes TF32 interesting

TF32 takes the **range from FP32** and the **precision from FP16**. So it has:
- The wide dynamic range of FP32 (no INF blowups from large activations).
- ~3 decimal digits of precision (~FP16-level).

This is a **better trade for many training workloads** than either FP16 (too narrow) or FP32 (too wasteful). NVIDIA tensor cores natively support TF32 input with FP32 accumulation since Ampere.

## How you actually use TF32

In PyTorch on Ampere+ GPUs, TF32 is **automatically used by `torch.matmul` and convolutions** unless you explicitly disable it via `torch.backends.cuda.matmul.allow_tf32 = False`. The user doesn't typically opt in — the framework opts in by default.

## TF32 vs BF16

- **Same range** (both 8 exponent bits).
- TF32 has **more precision** (10 vs 7 mantissa bits).
- BF16 uses **less memory** (16 vs 19 bits).

TF32 is a compute-format (mostly for tensor-core matmuls); BF16 is a storage-format (used for weights and activations). They're complementary.
