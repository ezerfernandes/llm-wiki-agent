# IA32 (32-bit x86)

**IA32** is Intel's 32-bit [[ISA|instruction set architecture]] — the dominant desktop ISA from the 386 (1985) through the mid-2000s, and the [[AssemblyLanguage|assembly language]] target used by [[dis-2-9-7-c-to-assembly|DIS Ch 2.9.7]]'s worked examples. Superseded for new code by [[X86_64|x86-64]] but still the canonical pedagogical target because (a) shorter instructions and simpler addressing modes than x86-64, (b) explicit stack-based parameter passing (the System V x86-64 ABI moved most args to registers — less visually pedagogical), (c) the `-m32` flag makes any modern [[GCC|`gcc`]] emit IA32 from C source.

## Register set

Eight general-purpose 32-bit registers: `%eax`, `%ebx`, `%ecx`, `%edx`, `%esi`, `%edi`, `%esp` (stack pointer), `%ebp` (base / frame pointer). Plus `%eip` (instruction pointer) and `EFLAGS` (status bits). [[dis-8-1-ia32-basics|Ch 8.1]] codifies this as *"eight 32-bit registers for data storage"* — **half the [[X86_64|x86-64]] count** (no `%r8`–`%r15`).

[[dis-2-9-7-c-to-assembly|Ch 2.9.7]]'s example uses `%eax` as the **accumulator** for multiplication and `%ebp` as the **frame pointer** locals are addressed off of.

## Subregister naming (letter substitution only)

[[dis-8-1-ia32-basics|Ch 8.1]] codifies the IA32 subregister scheme: `%eax` (32) → `%ax` (low 16) → `%al`/`%ah` (low/high bytes of `%ax`). The byte-level split (`%aH`/`%aL` form) is available for the first four registers (`%eax`/`%ebx`/`%ecx`/`%edx`); the index/pointer registers (`%edi`/`%esi`/`%esp`/`%ebp`) expose only the 16-bit low form. **No suffix-style names** like `%eaxd` — that scheme only exists in [[X86_64|x86-64]] for the new `%r8`–`%r15` registers.

## Memory operand syntax (AT&T)

`-8(%ebp)` reads as "8 bytes below the address `%ebp` points at" — the canonical pattern for accessing the first 32-bit [[LocalVariable|local variable]] in a function's [[StackFrame|stack frame]]. Conversely, `8(%ebp)` accesses the **first stack-passed parameter** — IA32's [[CdeclCallingConvention|cdecl]] convention passes all function arguments on the stack at positive `%ebp` offsets (8, 12, 16, ...) rather than in registers.

The full [[X86AddressingMode|`disp(base, index, scale)` addressing modes]] from [[dis-7-1-x86-64-basics|Ch 7.1]] apply unchanged at the IA32 surface — same six forms, same `scale ∈ {1, 2, 4, 8}` restriction.

## Size suffixes

[[dis-8-1-ia32-basics|Ch 8.1]] reduces the [[OperandSize|suffix table]] to three integer widths: `b` = 1 byte (`char`), `w` = 2 bytes (`short`), `l` = 4 bytes (`int` / `long` — *"long is 4 bytes on IA32, despite the name"*). The 64-bit `q` suffix from [[X86_64|x86-64]] has **no IA32 application** — no 64-bit registers exist. Float suffixes `s` / `d` carry over unchanged.

## Calling convention (cdecl)

IA32's standard ABI is [[CdeclCallingConvention|cdecl]]: **all function arguments pushed on the stack** (no register-based argument passing), caller cleans up the stack after return, return value in `%eax`. This is the **headline delta** from [[X86_64|x86-64]]'s [[SystemVCallingConvention|System V AMD64 ABI]], which passes the first six args in `%rdi` / `%rsi` / `%rdx` / `%rcx` / `%r8` / `%r9`. Inside a callee, IA32 stack-passed parameters are accessed as `8(%ebp)`, `12(%ebp)`, `16(%ebp)`, ... (positive offsets above the saved `%ebp`).

## Calling Ch 2.9.7's example into IA32

[[GCC|`gcc -m32 -S simpleops.c`]] emits assembly that uses `%ebp`-relative addressing for locals and the `addl` / `subl` / `imull` instruction family for arithmetic. The 32-bit `l` suffix (long = 32-bit on IA32, despite the name) distinguishes these from byte (`b`), word (`w`), and quad (`q`) variants.

## IA32 vs. x86-64

| Dimension | IA32 (`-m32`) | x86-64 (`-m64`, default) |
|---|---|---|
| Register width | 32-bit (`%eax`) | 64-bit (`%rax`) |
| Register count | 8 GP | 16 GP (`%r8`–`%r15` added) |
| Pointer width | 4 bytes | 8 bytes |
| Calling convention | Most args on stack | First 6 args in registers |
| Address space | 4 GiB virtual | 128 TiB user (effective) |

[[dis-2-9-3-voidstar|Ch 2.9.3]] used exactly this 4-byte-vs-8-byte pointer-width contrast to motivate [[VoidPointer|`void *`]]'s size uniformity.
