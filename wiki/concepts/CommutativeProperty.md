# Commutative Property

The **commutative property** says that **changing the order** of the numbers in an addition or a multiplication does not change the result. It holds for all [[RealNumbers|real numbers]]. OpenStax [[Prealgebra]] 2e (Chapter 7, [[prealgebra-2e-ch07-properties-of-real-numbers]], §7.2) states it for the two operations:

- **Commutative Property of Addition:** for real numbers `a, b`,  `a + b = b + a`  (e.g. `5 + 3 = 3 + 5 = 8`).
- **Commutative Property of Multiplication:** for real numbers `a, b`,  `a · b = b · a`  (e.g. `5 · 3 = 3 · 5 = 15`).

The mnemonic: **commutative = order.**

## Subtraction and division are NOT commutative
Order *does* matter for the other two operations, so they have no commutative property:

- `7 − 3 = 4` but `3 − 7 = −4`, so `7 − 3 ≠ 3 − 7`.
- `12 ÷ 4 = 3` but `4 ÷ 12 = 1/3`, so `12 ÷ 4 ≠ 4 ÷ 12`.

(A subtraction can be reordered only by first rewriting it as adding the opposite — `7 − 3 = 7 + (−3)` — turning it into an addition.)

## Using it
The commutative property lets you reorder addends or factors so that easier combinations come first — for example, pairing [[IdentityInverseZeroProperties|opposites]] that sum to 0, or pairing [[Reciprocal|reciprocals]] that multiply to 1, before finishing the computation. It is almost always used together with the [[AssociativeProperty|associative property]] (which lets you *regroup* what you've reordered). The standard convention that a coefficient is written before its [[Variable|variable]] (`m·4` written as `4m`) is itself an application of the commutative property of multiplication.

A common worked-example type also evaluates an expression two ways — in the given order and in a rearranged order — to show the answer is the same while one order is easier to compute.
