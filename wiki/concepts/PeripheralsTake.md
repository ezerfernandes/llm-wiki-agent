# `Peripherals::take()`

The **canonical embedded-Rust API for obtaining the singleton handle to a peripheral set**. Standardized across [[CortexMCrate|`cortex-m`]] (for [[ARMCortexM|Cortex-M]] core-architectural peripherals like [[SysTick]] / [[NVIC]] / SCB / DWT / MPU) and across every chip-specific [[PeripheralAccessCrate|PAC]] generated by [[Svd2Rust|`svd2rust`]] (for the chip's device peripherals like [[GPIO]] / [[USART]] / [[SPI]] / [[I2C]] / timers). Returns an `Option<Peripherals>` — `Some(p)` on the first call, `None` thereafter.

## Why it exists

[[rust-embedded-book-peripherals-borrowck]]'s exactly-one-instance precondition: the [[BorrowChecker]] needs exactly one Rust value per physical [[Peripheral|peripheral]]. `Peripherals::take()` is the **runtime gate** that manufactures that uniqueness at startup — the productionized form of the hand-rolled `Option<T>` + `replace` pattern from [[rust-embedded-book-peripherals-singletons]]. It is the [[Singleton|singleton]] pattern applied at the *peripheral-set* granularity (one struct containing all the chip's peripherals) rather than per-peripheral.

## Two implementation tiers

- **[[CortexMCrate|`cortex-m`]]'s `singleton!()` macro** — the lowest-level primitive. Used internally by `Peripherals::take()` and available for ad-hoc singletons in user code: `let buf: &'static mut [u8; 1024] = singleton!(: [u8; 1024] = [0; 1024]).unwrap();`.
- **`Peripherals::take()`** — the curated public API. Generated by both [[CortexMCrate|`cortex-m`]] (for `cortex_m::Peripherals`) and by [[Svd2Rust|`svd2rust`]] for each PAC (e.g. `lm3s6965::Peripherals::take()`). Returns the **whole** peripheral set at once; calling code then destructures.

```rust
fn main() -> ! {
    let core: cortex_m::Peripherals = cortex_m::Peripherals::take().unwrap();
    let device: lm3s6965::Peripherals = lm3s6965::Peripherals::take().unwrap();
    let mut syst = core.SYST;        // SysTick handle, by ownership
    let gpioa = device.GPIO_PORTA;   // GPIO bank handle
    // ...
}
```

## Higher-level abstractions on top

- **[[CortexMRTIC|`cortex-m-rtic`]]** — wraps `take()` so user code doesn't see the `Option`. `#[rtic::app(device = lm3s6965, peripherals = true)]` hands `init` a `cx.core: cortex_m::Peripherals` and `cx.device: lm3s6965::Peripherals` with **non-`Option`** fields. The framework guarantees `init` runs exactly once, so the unwrap is folded away.
- **[[HALCrate|HAL]] crates** — typically consume `Peripherals::take()` output and re-export it through type-state-encoded ([[TypeStateProgramming]]) handles for configured peripherals.

## Caveats

- **First-call winner; second call returns `None`** — calling `.unwrap()` on `take()` after the first call **panics**. The contract is "call exactly once, in `main` or `init`, before enabling interrupts".
- **Concurrent calls race** — `take()` is not `Sync` in the multi-call sense; concurrent callers from different interrupt contexts could both observe the `Option` as `Some` and both unwrap. Discipline (call only from `main` before unmasking IRQs) is part of the contract.
- **Per-crate, not global** — `cortex_m::Peripherals::take()` and `lm3s6965::Peripherals::take()` are **independent** singletons. A chip PAC's `Peripherals` does **not** include the core's `SysTick` — you must take both.
