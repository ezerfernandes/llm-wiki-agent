# Problem-Solving Strategy (Word Problems)

OpenStax [[Prealgebra]] 2e (Chapter 9, [[prealgebra-2e-ch09-math-models-and-geometry]], §9.1–9.2) packages applied math into one reusable **seven-step strategy** that turns a word problem into an equation and then a sentence answer. Every geometry, money, and number application in the chapter is an instance of this single procedure.

## The seven steps
1. **Read** the problem — make sure every word and idea is understood; reread until the situation is clear. Draw and label a figure when geometry is involved.
2. **Identify** what you are looking for.
3. **Name** the unknown — choose a [[Variable|variable]] to represent it, and express any related quantities in terms of that same variable.
4. **Translate** into an [[Equation|equation]] — restate the problem as one sentence, then convert it to algebra.
5. **Solve** the equation using the [[SolvingLinearEquations|general solving strategy]] and the [[PropertiesOfEquality|Properties of Equality]].
6. **Check** the answer in the *original* problem — is it reasonable?
7. **Answer** the question with a complete sentence.

## Translating words into algebra
The crux is step 4. Common cue words and their algebra (building on Ch 2's language of algebra):

| Phrase | Algebra |
|---|---|
| the **sum** of a number and 8 | n + 8 |
| three **more than** twice a number | 2n + 3 |
| the **difference** of a number and 12 | n − 12 |
| one number is 5 more than another | first = n, second = n + 5 |
| 8% **of** the original cost | 0.08c |

"**of**" signals multiplication (and points to the base in [[Percent|percent]] problems); "more than"/"less than" signal addition/subtraction.

## Problem types
- **Number problems** — a single unknown satisfying a stated condition.
- **Multi-number problems** — several unknowns expressed through one variable via their relationship (e.g. "one number is 5 more than another").
- **Consecutive integers** — integers that follow one another: first `n`, next `n+1`, then `n+2`. "The sum of two consecutive integers is 47" ⇒ n + (n + 1) = 47.
- **Percent problems** — translate a percent statement into an equation (e.g. "the increase was 8% of the original" ⇒ see [[Percent]]).

## Money applications (§9.2)
Coin, ticket, stamp, and mixture problems specialize the strategy with one organizing relationship:

> **number × value = total value**

Set up an organized table — **Type | Number | Value | Total Value** — with one row per item type and a final *total* row. Express each Number in terms of one variable (e.g. "nine more nickels than dimes" ⇒ nickels = d + 9; "twice as many quarters" ⇒ 2q), fill the Value column with the per-item worth (in cents or dollars, kept consistent), multiply across to get each Total Value, then **translate** by summing the Total Value column to the known grand total and solving.
