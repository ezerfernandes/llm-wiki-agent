# Lookahead Decoding

A **[[ParallelDecoding|parallel-decoding]] technique that uses the [[JacobiAlgorithm|Jacobi method]] to verify and refine K future tokens generated by the same decoder simultaneously.** Introduced by Fu et al. (2024); covered in [[ai-engineering-ch09-inference-optimization|*AI Engineering* Ch 9]].

## Procedure

> 1. **K future tokens are generated in parallel.**
> 2. **These K tokens are verified for coherence and consistency with the context.**
> 3. **If one or more tokens fail verification, instead of aggregating all K future tokens, the model regenerates or adjusts only these failed tokens.**
> 4. **The model keeps refining the generated tokens until they all pass verification and are integrated into the final output.**
>
> — Ch 9

This iterative regenerate-the-failed-ones pattern is the **Jacobi method** — multiple parts of a solution updated simultaneously and independently. Hence the family name **[[JacobiDecoding]]**.

## Comparison with Medusa

Both are parallel decoding, but:

| | Lookahead | [[Medusa]] |
|---|---|---|
| Token generators | Same decoder used for all K positions | Multiple decoder heads, each per-position |
| Verification | Jacobi iteration (regenerate failed) | Tree-based attention over per-head options |
| Requires training? | No | Yes (head training, base frozen) |

Lookahead is simpler to deploy because **no model changes are needed** — the same base model produces K candidates per step. Medusa requires architectural / training changes.

## Where it lives in the wiki

Lookahead decoding is one of three named techniques for "overcoming the autoregressive decoding bottleneck" in Ch 9, alongside [[SpeculativeDecoding|speculative decoding]] and [[Medusa|Medusa]]. The umbrella concept is [[ParallelDecoding]].
