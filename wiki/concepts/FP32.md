# FP32 — Single-Precision Float

The IEEE 754 binary32 format: **single-precision floating point**, 32 bits, 4 bytes per value. Per [[ai-engineering-ch07-finetuning|*AI Engineering* Ch 7]], the *"historical neural-network default"* before lower-precision formats became viable in the late 2010s.

## Bit allocation

- **Sign**: 1 bit.
- **Range** (exponent): 8 bits → range ±3.4 × 10³⁸.
- **Precision** (mantissa): 23 bits → ~7 decimal digits.

## Where FP32 still lives

- **NumPy / pandas** — Ch 7's quoted observation: *"as of this writing, FP64 is the default format for NumPy and pandas"* — actually FP64 historically, but FP32 is the practical default for ML tensors in those libraries.
- **Master copy in [[MixedPrecisionTraining|mixed-precision training]]** — keep an FP32 copy of weights; do forward/backward in FP16 or BF16; accumulate gradients in FP32.
- **Reference inference** — when comparing against lower-precision variants for accuracy.
- **Loss values** — even in mixed-precision training, loss values are typically computed in FP32 because small errors there can mis-direct parameter updates.

## Why FP32 isn't the inference default anymore

A 10B-parameter model in FP32 = 40 GB. The same model in FP16 = 20 GB. Inference quality is essentially unchanged for most workloads. The 2× memory + 2× compute throughput win makes lower-precision inference the default since the late 2010s.
