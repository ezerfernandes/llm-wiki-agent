# Similarity Measurement Against Reference Data

The second branch of [[ExactEvaluation|exact evaluation]] per [[ai-engineering-ch03-evaluation-methodology|*AI Engineering* Ch 3]]: evaluate generated outputs against curated [[ReferenceData|reference responses]]. *"Each example in the reference data follows the format (input, reference responses). An input can have multiple reference responses."*

## Four ways to measure similarity (Ch 3)

1. **Ask an evaluator** to judge whether two texts are the same (human or AI — the latter is the AI-as-judge approach).
2. **[[ExactMatch|Exact match]]** — does the generated response match a reference exactly?
3. **[[LexicalSimilarity|Lexical similarity]]** — how similar do the texts *look*? ([[bleu|BLEU]], [[ROUGE]], [[METEOR]], [[TER]], [[CIDEr]], [[EditDistance|edit distance]], [[NGramSimilarity|n-gram similarity]])
4. **[[SemanticSimilarity|Semantic similarity]]** — how close are they in *meaning*? ([[BERTScore]], [[MoverScore]], [[CosineSimilarity|cosine]] over [[Embedding|embeddings]])

Scores for exact match are binary; lexical and semantic scores are on a sliding scale (typically [0, 1] or [-1, 1]).

## Reference-based vs reference-free

Ch 3 introduces a key taxonomy:
- **[[ReferenceBasedMetric|Reference-based]]** — requires reference data (exact match, lexical, semantic).
- **[[ReferenceFreeMetric|Reference-free]]** — does not (e.g., [[Perplexity|perplexity]], [[LLMAsAJudge|AI-as-judge]], [[FunctionalCorrectness|functional correctness]]).

## The reference-data bottleneck

Per Ch 3: *"since this evaluation approach requires reference data, it's bottlenecked by how much and how fast reference data can be generated."* Reference data is generated by humans (the gold standard, but expensive and slow) or increasingly by AIs (cheaper, but still typically needs human review).

## Where reference-based similarity fails

- **Adept's [[Fuyu]]** was scored low on an image-captioning benchmark *"not because the model's outputs were wrong, but because some correct answers were missing in the reference data."*
- **WMT 2023 Metrics shared task** organizers *"found many bad reference translations in their data."* Low-quality references is one reason reference-free metrics now compete with reference-based ones on correlation to human judgment (Freitag et al. 2023).
- **HumanEval BLEU paradox** — Chen et al. 2021 found BLEU scores are similar for correct and incorrect Python solutions, so BLEU optimization is decoupled from [[FunctionalCorrectness|functional correctness]] on coding tasks.

## Reuse beyond evaluation

Ch 3 notes similarity measurements are also used for: retrieval and search ([[rag|RAG]]), ranking, clustering, anomaly detection, and data deduplication. *"Techniques discussed in this section will come up again throughout the book."*
