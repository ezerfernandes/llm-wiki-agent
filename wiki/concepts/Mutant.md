# Mutant

A **mutant** is a variant of the program under test that differs from the original by one small, *valid* change — an artificial fault seeded for [[MutationAnalysis|mutation analysis]]. A mutant the test suite detects (some test fails when run against it) is **killed**; a mutant that passes all tests **survives**. The [[MutationScore|mutation score]] is the proportion of (non-[[EquivalentMutant|equivalent]]) mutants killed.

Mutants are generated by a [[MutationOperator|mutation operator]] applied to the program's [[AbstractSyntaxTree|AST]] — e.g. replacing a statement with `pass`, or swapping `+` for `-`. Each mutant is intended to represent a *probable* programmer fault under the **Competent Programmer Hypothesis**: real residual bugs are mostly tiny, single-token deviations from a correct program.

## From The Fuzzing Book — Mutation Analysis
[[fuzzingbook-08-mutation-analysis|Ch 8]] represents each mutant with a `Mutant` class. In `MuFunctionAnalyzer` a `Mutant` is a *context manager*: its `__enter__` compiles the mutated source and installs the mutated function into `globals()`, and its `__exit__` marks the mutant `detected = True` if any exception (typically a failing [[Assertion|assert]]) escaped the `with` block, then restores the original. The `MuProgramAnalyzer` variant (`AdvMutant`) wires the mutated module into a [[UnitTesting|`unittest`]] test module and runs it through `MutantTestRunner` (with `failfast=True` and an `ExpectTimeout(1)` guard so an infinite-loop mutant is treated as killed). For the `triangle()` function the statement-deletion operator produces 5 mutants (one per `return`); `gcd()` yields 7. The chapter notes some generated mutants are [[EquivalentMutant|equivalent]] — semantically identical to the original — and so can never be killed.
