# `argilla/distilabel-intel-orca-dpo-pairs`

A preference-pair dataset hosted on Hugging Face by **[[Argilla|Argilla]]**, derived from **Intel's Orca DPO pairs** and processed via Argilla's `distilabel` AI-feedback library. Each row contains a prompt, a *chosen* completion, and a *rejected* completion — the canonical schema for [[DPO]] training.

## In Hands-On LLMs Ch 12

[[hands-on-llm-ch12-fine-tuning-generation-models|Ch 12]] uses this as its **worked DPO preference dataset** for the TinyLlama alignment run:

```python
from datasets import load_dataset

dpo_dataset = load_dataset(
    "argilla/distilabel-intel-orca-dpo-pairs", split="train"
)

# Filter to ~6,000 from the original ~13,000:
dpo_dataset = dpo_dataset.filter(
    lambda r:
        r["status"] != "tie" and
        r["chosen_score"] >= 8 and
        not r["in_gsm8k_train"]
)
```

The chapter notes the dataset is *"in part generated by ChatGPT with scores on which output should be accepted and which rejected"* — i.e., the chosen/rejected labels come from an LLM-as-judge step rather than from human pairwise comparisons.

### Filtering rationale

| Filter | Purpose |
|---|---|
| `status != "tie"` | Drop pairs where neither completion was preferred. |
| `chosen_score >= 8` | Keep only high-confidence preference labels. |
| `not in_gsm8k_train` | Avoid contamination with the GSM8k math benchmark training set. |

The third filter is notable as a [[DataLeakage|data-leakage]] precaution — Ch 12's evaluation discussion explicitly warns that public benchmarks (including GSM8k) suffer from training-set contamination.
