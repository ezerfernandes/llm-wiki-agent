## Summary

The first model-building chapter of [[d2l-preface|*Dive into Deep Learning*]]. Seven sections (`linear-regression.md`, `oo-design.md`, `synthetic-regression-data.md`, `linear-regression-scratch.md`, `linear-regression-concise.md`, `generalization.md`, `weight-decay.md`) walk from the [[LinearRegression|linear-regression]] model and squared loss through minibatch [[StochasticGradientDescent|SGD]], an [[ObjectOrientedDesign|OO]] training scaffold ([[Module]] / [[DataModule]] / [[Trainer]] inspired by [[PyTorchLightning|PyTorch Lightning]]), a synthetic-data sandbox, from-scratch + concise framework implementations, [[Generalization|generalization]] theory (training vs. population risk, IID, [[ModelSelection|model selection]], [[CrossValidation|K-fold CV]]), and finally [[WeightDecay|weight decay]] / $\ell_2$ regularization as the chapter's first concrete regularization technique. This is where D2L *substantively* opens its modeling layer: every later D2L architecture inherits the four primitives introduced here (parametric form, differentiable loss, minibatch-SGD optimizer, validation-set evaluation) and the OO `Module`/`DataModule`/`Trainer` scaffold.

## Key Claims

- **Linear regression is the simplest neural network**: $\hat y = \mathbf{w}^\top\mathbf{x} + b$ is a *single-layer fully-connected* net with one output neuron. D2L spends a chapter on it precisely because it exposes every component — parametric form, [[LossFunction|loss function]], optimizer, generalization analysis — without architectural complexity. "Even though we will never see any newly-built homes with precisely zero area, we still need the bias because it allows us to express all linear functions of our features."
- **Two loss motivations converge on squared error.** The functional motivation: $\ell^{(i)} = \tfrac12(\hat y^{(i)} - y^{(i)})^2$ penalizes outliers quadratically and is differentiable everywhere. The probabilistic motivation: under additive Gaussian noise $\epsilon\sim\mathcal{N}(0,\sigma^2)$, minimizing [[MeanSquaredError|MSE]] is exactly [[MaximumLikelihoodEstimation|maximum likelihood estimation]] (up to additive constants and a $1/\sigma^2$ scaling that the optimum is invariant to). The constant $\tfrac12$ is purely notational — it cancels under differentiation.
- **The closed-form (normal-equation) solution exists and is unique iff $\mathbf{X}$ has full column rank**: $\mathbf{w}^* = (\mathbf{X}^\top\mathbf{X})^{-1}\mathbf{X}^\top\mathbf{y}$. D2L treats this as the *exception, not the rule* — "you should not get used to such good fortune. […] The requirement of an analytic solution is so restrictive that it would exclude almost all exciting aspects of deep learning." The pedagogical point: SGD is taught here on a problem that doesn't need it, to teach the algorithm in its purest form.
- **[[MinibatchSGD|Minibatch SGD]] resolves the full-batch vs single-sample tradeoff**. Full-batch GD wastes work over data redundancy; pure SGD wastes hardware (matrix-vector ops are ~10× faster per element than scalar ops) and breaks layers like [[BatchNormalization|batch norm]]. The compromise: minibatch $\mathcal{B}_t$, "a number between 32 and 256, preferably a multiple of a large power of 2, is a good start." Update: $(\mathbf{w},b)\leftarrow(\mathbf{w},b) - \tfrac{\eta}{|\mathcal{B}|}\sum_{i\in\mathcal{B}_t}\partial_{(\mathbf{w},b)}\ell^{(i)}$. Two unavoidable hyperparameters: minibatch size and [[LearningRate|learning rate]] $\eta$.
- **The D2L OO scaffold = [[Module]] (model + loss + `configure_optimizers`) + [[DataModule]] (`train_dataloader` / `val_dataloader`) + [[Trainer]] (`fit(model, data)` with `max_epochs`)** — explicitly inspired by [[PyTorchLightning|PyTorch Lightning]]. Every later chapter subclasses these. Two infrastructural utilities support the notebook format: `add_to_class` (register a method on a class *after* instances exist, so explanations can interleave code blocks), and `HyperParameters.save_hyperparameters()` (auto-attach every `__init__` arg as `self.attr` with no boilerplate).
- **Synthetic data is pedagogically valuable**: generate $\mathbf{y} = \mathbf{X}\mathbf{w} + b + \boldsymbol\epsilon$ with known ground-truth $(\mathbf{w}=[2,-3.4]^\top,\ b=4.2,\ \sigma=0.01)$, then verify the trained model recovers them. The `SyntheticRegressionData(d2l.DataModule)` subclass is the running dataset for the entire chapter; later chapters reuse it as the trivial-but-honest sanity-check sandbox.
- **From-scratch ≠ production**. The scratch implementation builds [[StochasticGradientDescent|SGD]] manually: a `LinearRegressionScratch(d2l.Module)` with explicit `self.w` / `self.b`, a `forward` doing `matmul(X, w) + b`, a `loss` returning $\tfrac{(\hat y - y)^2}{2}$, an `SGD` class with `step`/`zero_grad`, a `configure_optimizers` returning it, and the `fit_epoch` loop (forward → backward → step → zero_grad). The concise version replaces all of it with `nn.LazyLinear(1)` + `nn.MSELoss()` + `torch.optim.SGD(self.parameters(), lr)` — same training loop, drastically fewer lines. The pedagogical commitment: "implementing things from scratch is the only way to make sure that you really know what you are doing."
- **PyTorch's `MSELoss` omits the $1/2$ factor**: framework `MSELoss` = $\tfrac{1}{n}\sum(\hat y - y)^2$, not the textbook $\tfrac{1}{2n}\sum(\hat y - y)^2$. A 2× difference in gradient magnitude — absorbed into the learning rate in practice but worth flagging when comparing scratch and concise runs.
- **[[Generalization|Generalization]] = training error vs. population risk under the IID assumption**. Training error is a *statistic* on $\mathcal{D}_{\text{train}}$; **generalization error** is an *expectation* under the true distribution $P(X,Y)$, which we never know — so we estimate it via a held-out test set, treating it as a sample-mean problem on a *fixed* classifier. "Absent any restriction on our model class, we cannot conclude, based on fitting the training data alone, that our model has discovered any generalizable pattern." Falsifiability framing: a hypothesis class capable of fitting any arbitrary labels has told us nothing about the world (Popper).
- **[[Underfitting|Underfitting]] vs. [[Overfitting|overfitting]] and the U-curve.** Underfitting: high training error + small generalization gap → use a richer model. Overfitting: low training error + large gap → fewer parameters, more data, or regularize. Polynomial curve fitting with $d \geq n$ achieves zero training error for *any* dataset; this is the textbook overfitting demo (Fig. `capacity-vs-error`). **Modern caveat** the chapter explicitly flags: "Note that overfitting is not always a bad thing. In deep learning especially, the best predictive models often perform far better on training data than on holdout data" — foreshadowing the double-descent / overparameterized regime.
- **Model selection requires three splits, not two.** Touching the test set during hyperparameter search overfits the test set — "if we overfit the test data, how would we ever know?" Hence train / validation / test, with hyperparameters chosen on validation only. When data is scarce, $K$-fold [[CrossValidation|cross-validation]] (training $K$ times, each time holding out a different fold) averages train+validation error across $K$ runs. The chapter is candid: most reported numbers in the book are *validation* accuracy, not true held-out test accuracy.
- **[[WeightDecay|Weight decay]] = $\ell_2$ regularization in optimizer form.** Augment the loss with $\tfrac{\lambda}{2}\|\mathbf{w}\|^2$; the SGD update becomes $\mathbf{w}\leftarrow(1-\eta\lambda)\mathbf{w} - \tfrac{\eta}{|\mathcal{B}|}\sum_{i\in\mathcal{B}}\mathbf{x}^{(i)}(\hat y^{(i)} - y^{(i)})$ — the leading $(1-\eta\lambda)$ factor literally *decays* the weight each step. Squared (not unsquared) norm chosen so the derivative is clean; $\ell_2$ (not $\ell_1$) spreads weight evenly across features (vs [[Lasso|lasso]]'s sparsity-inducing $\ell_1$ which is "fundamental in statistics" but a different goal). Bias is typically *not* regularized. **Frameworks integrate it into the optimizer** (PyTorch: `weight_decay=` in `torch.optim.SGD`; Keras: `kernel_regularizer=tf.keras.regularizers.l2(wd)`; Optax: `optax.chain(additive_weight_decay(wd), sgd(lr))`) — chosen because every parameter is touched per step anyway, so $\ell_2$ adds zero overhead. **Heuristic adopted throughout the book: weight decay applied to all layers of a deep network.**
- **Recovering ground truth ≠ accurate prediction.** Even on the noiseless synthetic dataset where exact recovery is theoretically possible (full-rank $\mathbf{X}$, Gaussian noise), SGD finds parameters *close to* but not equal to ground truth. For deep models with non-convex loss surfaces and many global minima, "we are often less concerned with recovering true underlying parameters, but rather with parameters that lead to highly accurate prediction" — a pragmatic alignment with [[Vapnik]]'s prediction-over-inference framing.

## Key Quotes

> "Strictly speaking, [the linear-regression model] is an *affine transformation* of input features, which is characterized by a *linear transformation* of features via a weighted sum, combined with a *translation* via the added bias." — `linear-regression.md`, Model section

> "It follows that minimizing the mean squared error is equivalent to the maximum likelihood estimation of a linear model under the assumption of additive Gaussian noise." — `linear-regression.md`, Normal Distribution and Squared Loss

> "While simple problems like linear regression may admit analytic solutions, you should not get used to such good fortune. […] The requirement of an analytic solution is so restrictive that it would exclude almost all exciting aspects of deep learning." — `linear-regression.md`, Analytic Solution

> "This problem — how to discover patterns that *generalize* — is the fundamental problem of machine learning, and arguably of all of statistics. We might cast this problem as just one slice of a far grander question that engulfs all of science: when are we ever justified in making the leap from particular observations to more general statements?" — `generalization.md`, opener

> "More commonly called $\ell_2$ regularization outside of deep learning circles when optimized by minibatch stochastic gradient descent, weight decay might be the most widely used technique for regularizing parametric machine learning models." — `weight-decay.md`, Norms and Weight Decay

> "That is why the method is sometimes called 'weight decay': given the penalty term alone, our optimization algorithm *decays* the weight at each step of training." — `weight-decay.md`, Norms and Weight Decay

## Contradictions

- **None direct.** All claims align with [[islr-seventh-printing]] (Ch.3 / Ch.6.2), [[mml-book]] (§9), and [[pml1-murphy]] (Ch.11) coverage of linear regression, OLS, ridge regression, and the bias-variance / model-selection story.
- **Framing tension (mild)**: D2L's pragmatic "we don't care about parameter recovery, only prediction accuracy" stance (citing Vapnik) sits in tension with [[BayesianLinearRegression]]'s emphasis on calibrated parameter uncertainty as a first-class deliverable. Different goals, both valid.
- **Notational note**: PyTorch's `nn.MSELoss` omits the $1/2$ factor that D2L's `linear-regression-scratch.md` and `weight-decay.md` use. Net effect = absorbed into $\eta$. Worth flagging for readers cross-comparing scratch / concise gradients.
