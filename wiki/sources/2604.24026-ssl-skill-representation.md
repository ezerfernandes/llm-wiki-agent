## Summary
Liang, Wang, Liang & Liu (Peking University) argue that the dominant SKILL.md text-heavy format collapses semantically distinct properties — invocation interface, execution phases, action / resource-use evidence — into one natural-language surface, creating a representational bottleneck for skill discovery and risk assessment. They introduce **SSL (Scheduling-Structural-Logical)**, the first explicit three-layer typed JSON representation for agent skill artifacts, grounded analogically in Schank & Abelson's classical cognitive-linguistic theories. An LLM-based **normalizer** converts existing SKILL.md files into SSL. Empirically, SSL beats text-only baselines on Skill Discovery (MRR@50 **0.649 → 0.729**) and Risk Assessment (macro F1 **0.409 → 0.509**).

## Key Claims
- **Representational bottleneck.** A single SKILL.md entangles invocation interface, scene-level execution structure, and action/resource-use signals — forcing every downstream consumer to re-parse the long, noisy, sometimes incomplete prose.
- **Three layers grounded in classical theory.**
  - **Scheduling layer** (Memory Organization Packets, Schank 1980): goal, tags, intent signature, inputs/outputs — invocation-level signals.
  - **Structural layer** (Script Theory, Schank & Abelson 1977): ordered scenes (prepare / acquire / act / verify / finish / retry) with expectations and transitions.
  - **Logical layer** (Conceptual Dependency, Schank 1972): atomic actions (READ / CALL / WRITE / EXPORT / CHECK) tagged with the resources they touch (local files, credentials, external API).
- **Source-grounded, not source-replacing.** SSL is paired with the original SKILL.md, not a substitute; combined views (SKILL.md + SSL) win on Risk Assessment, suggesting SSL exposes complementary evidence.
- **Why Schank/Abelson over Minsky/Fillmore.** MOP / Script / CD distinguish goal-oriented contexts, ordered activities, and primitive operations — closer to the three kinds of evidence SSL disentangles than Minsky's frame slots or Fillmore's frame semantics.
- **Empirical results.** Skill Discovery: rich SSL-derived description view raises MRR@50 from 0.649 to 0.729 on 431 intent-level queries against 6,184 skills. Risk Assessment: combined SKILL.md + SSL view raises macro F1 from 0.409 to 0.509 across six risk dimensions on 252 labelled skills.
- **Open release.** SSL guidelines, normalizer prompts, 6,184-skill annotated corpus, 431 intent queries, and 252 risk-labelled skills released under COOLPKU/SSL.

## Key Quotes
> "Skills are still represented by text-heavy artifacts ... whose machine-usable evidence remains embedded largely in natural-language descriptions."
> "Semantically distinct properties are collapsed into a single textual surface."
> "SSL is hence designed to represent machine-facing skill artifacts."

Aligned with [[2605.00424-skills-as-verifiable-artifacts]] on treating skills as artifacts requiring formal-ish handling, but at the representation layer rather than the trust layer; the two papers compose: SSL exposes the facts that biconditional-style verification would need to check.
