## Summary

Section 2.2 of [[DiveIntoSystems]] introduces the [[CLanguage|C]] **[[Pointer|pointer variable]]** — the language feature *forward-referenced* from [[dis-1-1-getting-started|Ch 1.1]], [[dis-1-2-input-output|Ch 1.2]] (where the [[AddressOfOperator|`&` operator]] first surfaced inside [[Scanf|`scanf`]] without yet being explained), [[dis-1-5-arrays-strings|Ch 1.5]] (where [[CArray|arrays]]' [[PassByReference|pass-by-reference]] was promised to be reconciled via pointers), [[dis-1-6-structs|Ch 1.6]] (where the [[ArrowOperator|`->`]] operator and pointer-to-struct field access were named-and-deferred), and [[dis-1-7-summary|Ch 1.7]] (which explicitly named *"pointer variables"* and *"dynamic memory allocation"* as Ch 2's two big deferrals). The section's headline definition: *"C's pointer variables provide a level of indirection to accessing program memory."* A **[[Pointer|pointer]] variable stores the [[CMemoryAddress|memory address]] of another variable**, and the language pairs three syntactic moves to make it useful: (1) [[PointerDeclaration|declaration]] via `type_name *var_name;` — the **`*` in a declaration is part of the type**, not an operator — yielding types like `int *` ("pointer to `int`") or `char *` ("pointer to `char`"); (2) initialization via the [[AddressOfOperator|`&` address-of operator]] (`ptr = &x;`) — finally explained as a first-class language move, not just `scanf`-magic; or via the special value [[NullPointer|`NULL`]] (`ptr = NULL;`) which *"indicates that it doesn't refer to any particular address"*; and (3) access to the pointee via the **unary [[DereferenceOperator|`*` dereference operator]]** (`*ptr = 8;` writes the pointee, `y = *ptr + 3;` reads it). The chapter motivates pointers with five use cases the rest of Ch 2 (and most of Part II) will rely on: **pass-by-pointer parameters** ([[PassByPointer|the workaround for]] [[dis-1-4-functions|Ch 1.4]]'s [[PassByValue|pass-by-value]] rule that lets a function mutate the caller's storage), **[[DynamicMemoryAllocation|dynamic memory allocation]]** (forward-referenced to Ch 2.4), **efficient passing of large data structures** (passing one [[CMemoryAddress|address]] instead of [[StructAssignment|copying a whole]] [[CStruct|struct]]), **[[LinkedDataStructure|linked dynamic data structures]]** (linked lists, trees), and **byte-reinterpretation** (looking at the same memory through different pointer types — the substrate for the [[BufferOverflow|buffer-overflow]] / type-pun stories of later chapters). The section closes with the two **safety rules** pointer-using C programs live by: **a [[PointerType|pointer]] must be initialized before use** (an uninitialized pointer holds a garbage address; dereferencing it crashes or — worse — corrupts arbitrary memory), and **[[NullPointer|`NULL`]] must never be dereferenced** (`*NULL` is undefined behavior, typically a [[SegmentationFault|segmentation fault]]); the chapter's defensive idiom is the short-circuit guard `if (ptr != NULL) { *ptr = 6; }` — a direct callback to [[ShortCircuitEvaluation|short-circuit evaluation]] from [[dis-1-3-conditionals-loops|Ch 1.3]]. Pointer **arithmetic**, pointer-to-pointer, `void *`, and the [[ArrowOperator|`->`]] / pointer-to-struct story are *referenced and deferred* to later Ch 2 sections.

## Key Claims

- **A [[Pointer|pointer]] is *a level of indirection*.** Per the chapter: *"C's pointer variables provide a level of indirection to accessing program memory."* A pointer variable holds the [[CMemoryAddress|address]] of another variable — *not* its value — so reading/writing the pointee requires one extra step ([[DereferenceOperator|`*`]]). This is the conceptual upgrade [[dis-1-2-input-output|Ch 1.2]]'s [[AddressOfOperator|`&`]] / [[CMemoryAddress|memory-address]] story was foreshadowing: an address is finally a *value that can be stored in a variable of its own*.
- **Pointers exist to unlock five capabilities [[CLanguage|C]] otherwise lacks.** The chapter enumerates: (1) *"implement functions whose parameters can modify values in the caller's stack frame"* — i.e. [[PassByPointer|pass-by-pointer]], the workaround for [[dis-1-4-functions|Ch 1.4]]'s [[PassByValue|pass-by-value]] rule; (2) *"dynamically allocate (and deallocate) program memory at runtime"* — forward-references [[DynamicMemoryAllocation|dynamic memory allocation]] (Ch 2.4); (3) *"efficiently pass large data structures to functions"* — pass one [[CMemoryAddress|address]] rather than copy a 76-byte [[CStruct|struct]] per [[dis-1-6-structs|Ch 1.6]]; (4) *"create linked dynamic data structures"* — the substrate for linked lists / trees / graphs; (5) *"interpret bytes of program memory in different ways"* — the type-punning substrate for the [[BufferOverflow|buffer-overflow]] story of Ch 2.6.
- **[[PointerDeclaration|Pointer declaration syntax]] is `type_name *var_name;`.** Two canonical examples: `int *ptr;` ("`ptr` stores the memory address of an `int`") and `char *cptr;` ("`cptr` stores the memory address of a `char`"). The chapter is explicit that the **`*` in a declaration is part of the type spelling**, not the unary dereference operator that appears in expressions — same lexeme, two different syntactic roles. The declared type carries the [[PointerType|pointee's static type]]: `int *` and `char *` are *different incompatible types* even though both ultimately hold an address.
- **The [[PointerType|static type]] of a pointer determines what it may point to.** The chapter shows this with the type-mismatch error: `cptr = &x;` is **wrong** when `cptr` is `char *` and `x` is `int` — *"`cptr` expects a char address, but `x` is an `int`"*. Assigning across pointer types yields a compiler warning and *"unpredictable behavior"* at runtime. This is the language's only barrier between the unsafe operations the [[BufferOverflow|buffer-overflow]] story exploits and well-behaved programs — and the reason `void *` (deferred) requires explicit casts.
- **Initialization: [[AddressOfOperator|`&`]] yields a [[Pointer|pointer]] value.** Per the chapter pattern: `int x; ptr = &x;` — *"`ptr` gets the address of `x`; pointer 'points to' `x`"*. This is the *first time* `&` is presented as a general-purpose language move; [[dis-1-2-input-output|Ch 1.2]] used it only as a [[Scanf|`scanf`]] argument. The expression `&x` has type *pointer-to-`x`'s-declared-type* — `int x; &x;` is `int *`, `char ch; &ch;` is `char *` — and may be assigned to any compatible [[Pointer|pointer]] variable, returned from a function, or compared.
- **[[NullPointer|`NULL`]] is the *no-address* pointer value.** Per the chapter: *"Any pointer can be given the special value `NULL`, which indicates that it doesn't refer to any particular address."* `NULL` is a macro (`<stddef.h>` / `<stdio.h>`, defined as `((void *)0)` on most platforms); it is **assignable to any pointer type** and is the conventional *initialized but not yet pointing anywhere* state. **Dereferencing `NULL` is undefined behavior** — in practice a [[SegmentationFault|segmentation fault]] on hosted OSes — so production C uses the [[ShortCircuitEvaluation|short-circuit guard]] `if (ptr != NULL) { *ptr = 6; }` (a callback to [[dis-1-3-conditionals-loops|Ch 1.3]]'s `if (p != NULL && *p == 0)` idiom).
- **The [[DereferenceOperator|`*` dereference operator]] reads and writes the pointee.** The chapter's canonical example: `ptr = &x; *ptr = 8;` — *"the memory location `ptr` points to is assigned `8`"* — and `y = *ptr + 3;` reads the pointee. The asymmetry to learn: `ptr` (the pointer) is *not* `*ptr` (the pointee); assigning to one is not assigning to the other. The unary `*` in an *expression* dereferences; the same lexeme in a *declaration* spells the pointer type — the chapter's load-bearing dual-role disambiguation.
- **Pointers must be initialized before use.** An uninitialized pointer holds an arbitrary garbage address; dereferencing it is **undefined behavior** — likely a crash, occasionally a silent memory corruption that surfaces unpredictably later. The chapter's example: `ptr = 20; *ptr = 6;` — assigning a literal integer to a pointer compiles (with a warning) and crashes at the dereference because `20` is almost certainly not a valid address in the process's [[AddressSpace|address space]]. The discipline this prescribes: **assign either `&something` or `NULL` to every pointer at declaration**, and check for `NULL` before dereferencing.
- **Two assignment views, one operator.** Given `int *ptr;` and `int x;`, the assignments split cleanly: **`ptr = &x;`** changes *which variable `ptr` points to* (reassigns the pointer itself); **`*ptr = 8;`** changes *the value of the variable `ptr` points to* (writes through the pointer to `x`). The same `=` syntax, the same `ptr` name on the left, but the unary `*` flips between *modifying the pointer* and *modifying the pointee*. Mastering this distinction is the chapter's central learning objective.
- **Pointers reconcile [[dis-1-5-arrays-strings|Ch 1.5]]'s [[PassByReference|pass-by-reference]] contradiction.** [[dis-1-4-functions|Ch 1.4]] declared [[CLanguage|C]] pure [[PassByValue|pass-by-value]]; [[dis-1-5-arrays-strings|Ch 1.5]] then noted that [[CArray|arrays]] pass *by reference* and promised a Ch 2 reconciliation. Ch 2.2 delivers it: arrays decay to a pointer to their first element at the call site, the **pointer value is passed by value** (the rule from Ch 1.4 still holds), but because the pointer addresses the caller's storage, any [[DereferenceOperator|dereference]] inside the callee reaches and may mutate that storage — *"pass-by-reference"* is just *"pass-by-value of a pointer"*. The same mechanism (pass-by-pointer) supplies the output-parameter idiom that [[dis-1-4-functions|Ch 1.4]] had no answer for.
- **Pointers also reconcile [[dis-1-6-structs|Ch 1.6]]'s [[StructAssignment|struct-copy]] cost.** [[CStruct|Struct]] [[PassByValue|pass-by-value]] copies every byte (≥ 76 bytes for the canonical `studentT`); pass-by-pointer copies one address. The [[ArrowOperator|`->`]] operator named-and-deferred in Ch 1.6 (`p->field` ≡ `(*p).field`) is the readable way to access struct members through a pointer parameter — Ch 2.2 provides the underlying machinery, later Ch 2 sections will give the idiom.

## Key Quotes

> "C's pointer variables provide a level of indirection to accessing program memory." — the section's headline definition; the *level-of-indirection* phrase recurs throughout Ch 2's subsequent sections and the OS / virtual-memory chapters of Part II.

> "Any pointer can be given the special value `NULL`, which indicates that it doesn't refer to any particular address." — defines [[NullPointer|`NULL`]] as the *no-address* state and is the load-bearing claim behind the `if (ptr != NULL)` guard idiom.

> "`int *ptr;   // stores the memory address of an int (ptr "points to" an int)`" — the canonical [[PointerDeclaration|pointer declaration]] form; comment makes explicit the *points-to* metaphor that the rest of the chapter (and the wiki's [[Pointer]] page) relies on.

> "`ptr = &x;    // ptr gets the address of x, pointer "points to" x`" — finally explains the [[AddressOfOperator|`&` operator]] as a general-purpose move, not just a [[Scanf|`scanf`]] argument; the *first time the corpus shows an address being stored into a variable of its own*.

> "`ptr = &x;   /* initialize ptr to the address of x (ptr points to variable x) */`<br>`*ptr = 8;   /* the memory location ptr points to is assigned 8 */`" — the canonical [[DereferenceOperator|dereference]] example pairing initialization and writing through the pointer.

## Contradictions

- **No contradictions; *one reconciliation*.** Ch 2.2 explicitly *reconciles* the apparent [[PassByValue|pass-by-value]] vs. [[PassByReference|pass-by-reference]] contradiction between [[dis-1-4-functions|Ch 1.4]] and [[dis-1-5-arrays-strings|Ch 1.5]]: the [[CLanguage|C]] rule is *always pass-by-value*, but when the value being passed is a **[[Pointer|pointer]]** (as it is for [[CArray|arrays]] via decay, or explicitly via [[PassByPointer|pass-by-pointer]]), the callee can [[DereferenceOperator|dereference]] it to reach the caller's storage — yielding *pass-by-reference semantics* without breaking the *pass-by-value mechanism*. No prior claim is overturned.
