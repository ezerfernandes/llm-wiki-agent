# ECG-Chat — A Large ECG-Language Model for Cardiac Disease Diagnosis

**Zhao, Kang, Zhang, Han & Chen ([[chinauniversityofgeosciences|China U. Geosciences]] / [[beijingnormaluniversity|Beijing Normal U.]] / [[esigelec|ESIGELEC]] / [[southernuniversityofscienceandtechnology|SUSTech]] / [[universityofliverpool|U. Liverpool]]), arXiv:2408.08849v2, 16 April 2025.** First end-to-end **[[MultimodalLLM|multimodal LLM]] for [[ECG]]-based cardiac-disease report generation** — pairs a [[CoCa]]-style [[ECGEncoder|ECG encoder]] with **[[Vicuna13B|Vicuna-13B]]** under **[[lora]]** fine-tuning, mitigates hallucination through **[[GraphRAG]]** over seven cardiology textbooks, and tunes the diagnostic prompt with **[[DSPy]]**. Code: <https://github.com/YubaoZhao/ECG-Chat>.

## Summary

ECG-Chat tackles the **text-signal modality gap** that has kept general-purpose [[MultimodalLLM|MLLMs]] from passable [[ECG]] interpretation. The architecture is a two-stage feature-alignment + instruction-tuning recipe inspired by [[LLaVA15|LLaVA-v1.5]]: (1) a [[CoCa]]-style dual contrastive + captioning loss pretrains a **12-layer 1d-ViT** [[ECGEncoder|ECG encoder]] over **805K** ECG-text pairs from [[MIMIC-IV-ECG]] + [[ChampanShaoxingNingbo|CSN]] + [[ShandongProvincialHospital|SPH]]; (2) a frozen ECG encoder feeds a 2-layer MLP projector into [[Vicuna13B]], which is then [[lora]]-fine-tuned (rank 32, AdamW, [[ZeRO]] memory optimization, 8×V100 32GB) on the **[[ECGInstruct|ECG-Instruct]]** dataset (19K diagnosis + 25K dialogue, GPT-4o-generated).

Two engineering primitives carry most of the empirical lift. **[[WaveformDataEnhancement|Waveform Data Enhancement (WDE)]]** appends [[NeuroKit2]]-extracted lead-II morphology (RR interval, PR interval, QRS complex duration, QT/QTc, P/R/T peaks) to the text report **before** contrastive training — without it, [[CoCa]] zero-shot retrieval R@1 on [[PTB-XL]] sits at 2.14 / 2.37; **with WDE it jumps to 64.7 / 71.6**. **[[DiagnosisDrivenPrompt|Diagnosis-Driven Prompt (DDP)]]** runs a linear classifier on ECG features, embeds the top labels as text in the LLM prompt (*"Sinus rhythm is present; Left bundle branch block is present"*), then asks Vicuna to write the report. DDP ablation: Disease-F1 1.76→22.33, Form-F1 0.98→17.35, Rhythm-F1 13.04→43.39, BLEU-1 15.91→32.27, METEOR 29.39→35.10.

**Hallucination is engineered out at two layers.** [[GraphRAG]] builds a knowledge graph from seven authoritative cardiology textbooks — *ECG Workout*, *Manual of Cardiovascular Medicine*, *Medical Student Survival Skills: ECG*, *Cardiology Subspecialty Consult*, *The ECG Made Easy*, *The ECG In Practice*, *Arrhythmia Recognition* — runs Louvain community detection over it, and supplies retrieved passages as RAG context. [[DSPy]] (Soylu, Potts & Khattab 2024) performs automated prompt tuning on the [[ECGInstruct|ECG-Instruct]] dataset to compose patient data + retrieved knowledge into a coherent diagnostic context. **[[RAGAS]] ablation** (123-pair [[ECGExpertQA]]): no GraphRAG/no DSPy → Faithfulness 39.87; +GraphRAG only → 76.60; +DSPy only → 71.57; **+both → 82.12**. The two modules are largely orthogonal — GraphRAG lifts Faithfulness and Answer Relevancy, DSPy lifts Context Recall and Summarization Score.

The empirical claim: **a single 13B model with ECG encoder + textbook-RAG + automated prompt tuning achieves SOTA on zero-shot ECG-report retrieval (R@1 64.7 vs prior best CoCa 2.14), ECG classification (F1 52.8 PTB-XL / 80.1 CPSC2018), and report generation (BLEU-1 32.27, METEOR 35.10), and matches the readability of GPT-4o-translated reference reports** while remaining specialized to a single physiological modality.

## Key Claims

- **The ECG-text modality gap is closable with waveform-augmented contrastive learning.** Most open ECG datasets ([[MIMIC-IV-ECG]], [[ChampanShaoxingNingbo|CSN]], [[ShandongProvincialHospital|SPH]], [[PTB-XL]], [[CPSC2018]]) have *"structured, terminological, and highly repetitive phrase combinations"* — the same boilerplate report applied to many records. Without intervention, contrastive loss can't separate samples; **WDE** breaks the tie by appending **per-record waveform morphology** (RR / PR / QRS / QT / P/R/T peaks via [[NeuroKit2]]) to the text side. Result on PTB-XL R@1: All-Grid 0.21, MERL 1.00, ALBEF 1.36, CoCa 2.14, **CoCa+WDE 64.7** — a 30× jump.
- **Diagnosis-Driven Prompts cut report-generation hallucination at the LLM layer.** A separate linear classifier on the [[ECGEncoder]]'s output produces SCP-Code probabilities; labels above threshold get rendered as English-sentence facts (*"Sinus rhythm is present"*) and **inserted into Vicuna's prompt before report generation**. This is a structural mirror of the [[DiagnosisDrivenPrompt|DDP method]] used in radiology MLLMs ([[Promptmrg]], [[Diallama]]). Without DDP, Vicuna-13B *"prefers only a few specific responses"* (low recall on rare labels); with DDP, F1 rises 22 points on Disease, 16 on Form, 30 on Rhythm.
- **GraphRAG + DSPy is the right hallucination-mitigation stack for narrow medical domains.** The two modules are **complementary**: GraphRAG injects authoritative facts (boosting Faithfulness 39.87→76.60) but cannot organize them into a clinically useful answer shape; DSPy automates prompt design (boosting Context Recall 9.03→27.57 alone) but cannot supply missing domain knowledge. Both together cross 80+ on Faithfulness, Answer Relevancy, Context Utilization, Context Entity Recall, and Summarization Score simultaneously — no single ablation gets there.
- **ECG-Instruct (19K diagnosis + 25K dialogue) is the first open ECG instruction-tuning corpus.** Built by giving GPT-4o the [[MIMIC-IV-ECG]] free-text report + [[NeuroKit2]]-extracted waveform data + a randomly-selected ECG-interpretation question, plus a *"negative-example"* prompt regime that randomly injects fake diagnostic features so the model learns to refute them. Total: 45,044 ECG samples / 325,730 sentences / 3.29M-word vocabulary / 6,319 distinct vocabularies. Released as the paper's primary dataset contribution.
- **Scalability is data-bound, not parameter-bound.** Ablation Table VI: holding the encoder at 85M parameters, training on 80K vs 402K vs 805K records moves R@1 from 0.86→40.1→**64.7** and PTB-XL F1 from 45.42→51.2→**52.8**. Changing encoder size from 43M to 128M at fixed data moves R@1 from 63.5→68.7 (modest) and PTB-XL F1 from **54.6→54.4** (no gain). The dominant bottleneck on this task is **labeled ECG-text pairs**, not encoder capacity — consistent with the broader [[scalinglaws]] picture that data scales harder than parameters in low-data regimes, though here the curve is even more lopsided than typical.
- **Med-CPT is the right text encoder for ECG retrieval; BioLinkBert wins reconstruction.** Ablation Table V: BioLinkBert R@1 72.7 / 76.6 vs Med-CPT 64.7 / 71.6 on retrieval; on classification it inverts — Med-CPT PTB-XL F1 52.8 / CPSC 80.1 beats BioLinkBert's 52.7 / 78.3. ECG-Chat ships with Med-CPT as the production choice given the classification bias of clinical deployment.

## Key Quotes

> "The structured, terminological, and highly repetitive phrase combinations poses challenge for the current Vision-Language models to migrate to the ECG field. Consequently, no model currently addresses both ECG report generation and question answering effectively." — §1.

> "Optimizing the contrastive loss is the way that ECG features align with the text reports... $\mathcal{L}_{con} = -\tfrac{1}{N}(\mathcal{L}_{e2t} + \mathcal{L}_{t2e})$." — §III-B, equations (1)–(3).

> "For the training data, we did not use diagnostic reports directly. Given the scarcity of datasets with text reports, we appended corresponding waveform data to the reports... This approach artificially increases the distinction between samples, even when reports are identical, helping prevent contrastive loss from failing to converge during small-batch training." — §III-B, the WDE rationale.

> "Inspired by the Diagnosis-Driven Prompt (DDP) method in radiology, we adapted DDP for ECG report generation... A linear layer classifies ECG feature vectors, embedding the most probable label in the prompt (e.g., 'The label description is present.')." — §III-C.

> "Our approach integrates three essential components to enhance the generation of ECG diagnostic reports. First, the GraphRAG component constructs a comprehensive knowledge graph from seven authoritative cardiology textbooks... Second, DSPy is employed for automated prompt tuning, which dynamically integrates patient data with retrieved knowledge, producing accurate and contextually relevant outputs. Finally, the LaTeX-based pipeline automates the creation of structured clinical reports." — §III-D.

> "We employ a DSPy component, trained on the ECG-Instruct dataset, to perform automatic prompt tuning. DSPy leverages GraphRAG to retrieve relevant knowledge such as symptom causes, medication information, and clinical guidelines, and combines this knowledge with the patient's vital signs and cardiology diagnostic data to form a comprehensive medical context." — Appendix B.

> "Without GraphRAG and DSPy, the model's performance is relatively poor, with a Faithfulness score of 39.87 and Answer Relevancy score of 32.56, among others. Introducing the GraphRAG module results in a significant improvement in Faithfulness (76.60) and Answer Relevancy (68.29). Meanwhile, incorporating the DSPy module leads to improvements in Context Recall (27.57) and Summarization Score (47.72)." — Appendix F.

> "It can be seen that the number of model parameters has little impact on the results. When increasing the amount of training data, the model effect can be significantly improved, especially on retrieval tasks." — Appendix F-c (Scalability).

## Method — exact knobs

- **ECG encoder**: 12-layer 1d-ViT, patch size 50, hidden 768, 12 heads, MLP 3072. AdamW, lr 1e-4, weight decay 0.1, 20 epochs, batch 128 per GPU. Three augmentations: baseline wander, cut mix, random masking ([[TorchECG|torch_ecg]]). Loss weights $\lambda_{con} = 1.0$, $\lambda_{cap} = 2.0$.
- **Text encoder**: [[MedCPT]], fine-tune last 2 layers, embed dim 512, 6-layer transformer decoder. Other ablated encoders: [[BioLinkBert]], [[BioClinicalBert]].
- **Projector**: 2-layer MLP between frozen ECG encoder and Vicuna-13B.
- **LLM**: [[Vicuna13B]]. AdamW + cosine LR. Stage 1 (feature alignment) — projector only, 1 epoch. Stage 2 (instruction tuning) — projector + Vicuna under [[lora]], 3 epochs. [[ZeRO]] for memory; 8×V100 32GB GPUs.
- **Datasets**: training = MIMIC-IV-ECG 788,822 + CSN 40,637 + SPH 20,616 = ~850K (Table-VI says 805K mixed). Eval = PTB-XL 21,837 (2K test) + CPSC2018 6,877.
- **Instruction-tuning datasets**: ECG-Instruct-Diagnosis 20,258 single-turn QA (caption length avg 66.77 words, 4.10 sentences/caption) + ECG-Instruct-Conversations 24,786 multi-turn (4–30 rounds, avg 78.36 words/conv, 9.79 sentences/conv). Both built by GPT-4o on [[MIMIC-IV-ECG]] data.
- **Evaluation knowledge base**: [[ECGExpertQA]] = 123 QA pairs from ChatGPT-4o + expert curation.
- **Report generation pipeline**: [[plasTeX]] (Smith, GitHub) → structured LaTeX → six sections (Patient Information / Medical History / ECG Data Analysis / Pathological Analysis / Diagnosis / Recommendations).

## Connections

- [[CoCa]] — the contrastive-captioner architecture ECG-Chat adopts; the WDE result above is the headline empirical claim that a CoCa-style dual loss generalizes to ECG-text when the text side is augmented with morphology.
- [[Vicuna13B]] — the base LLM; ECG-Chat is the wiki's first record of a LoRA-tuned Vicuna for a physiological-signal modality.
- [[lora]] — the parameter-efficient fine-tuning method. ECG-Chat applies LoRA to Vicuna-13B's attention projections; rank/alpha/lr not stated but [[ZeRO]] + 8×V100 budget implies modest rank.
- [[DSPy]] — explicitly cited as the prompt-tuning module that *"dynamically integrates patient data with retrieved knowledge."* The wiki's first record of DSPy used inside a **medical multimodal pipeline**, complementing the [[DSPyOptimizers|Optimizer]] catalog's text-only-task framing.
- [[GraphRAG]] — Microsoft's knowledge-graph RAG (Edge et al. 2024). ECG-Chat constructs the graph from seven cardiology textbooks via Louvain community detection. First wiki record of GraphRAG applied to a clinical specialty corpus.
- [[Hallucination]] — ECG-Chat's framing of *"semantic deviations caused by generated text that does not align with the actual situation."* The paper's three-stage mitigation (textbook RAG + DSPy prompt tuning + LaTeX template enforcement) is a domain-specific instance of the [[LLMModuloFramework|LLM-Modulo]] Generate-Test-Critique pattern, with GraphRAG as the knowledge critic and LaTeX as the format critic.
- [[LLaVA15]] — the visual-multimodal precedent ECG-Chat directly mirrors (two-layer MLP adapter, two-stage feature-alignment + instruction-tuning).
- [[bleu]], [[F1Score]] — primary NLG and CE metrics. ROUGE-L, METEOR, and the [[RAGAS]] suite (Faithfulness / AR / CR / CP / CU / CER / SS) supply the rest of the evaluation surface.
- [[MIMIC-IV-ECG]], [[PTB-XL]], [[CPSC2018]], [[ChampanShaoxingNingbo]], [[ShandongProvincialHospital]] — open ECG datasets composing the 805K-record training mix and the 8.9K-record evaluation mix.
- [[NeuroKit2]] — the Python toolbox supplying the lead-II waveform features (RR / PR / QRS / QT / P/R/T peaks) WDE appends to text reports.
- [[ECGInstruct]] — 19K diagnosis + 25K conversation GPT-4o-generated instruction-tuning dataset (paper's data contribution).
- [[ECGExpertQA]] — 123-pair RAGAS evaluation knowledge base (paper's eval contribution).
- [[WaveformDataEnhancement]] — the contrastive-training trick (text + waveform features) that breaks the 2→64 R@1 barrier.
- [[DiagnosisDrivenPrompt]] — the classifier-into-prompt trick that lifts report-generation F1 by 20+ points.

## Contradictions / tensions

- **vs [[2507.19457-gepa|GEPA]]'s prompt-vs-RL framing.** GEPA argues prompt-space optimization beats weight-space RL in low-data regimes. ECG-Chat does **both**: LoRA weight updates *and* DSPy prompt tuning, in the same pipeline. No ablation isolates whether the DSPy lift would survive without the LoRA fine-tune — the paper's RAGAS table holds LoRA fixed and only ablates RAG/DSPy. Open question whether the GEPA framing dominates in the clinical multimodal setting.
- **vs [[2507.03152-medval|MedVAL]]'s LM-as-judge stance.** MedVAL argues clinical text validation should be done by a *separate* small LM-as-judge (MedVAL-4B / QLoRA) fine-tuned on physician-annotated error taxonomies. ECG-Chat handles validation by **prompt construction** (DDP + GraphRAG) inside the *same* model that generates the report — no external judge. The two papers occupy adjacent points in the medical-text-validation design space: MedVAL = post-hoc judge, ECG-Chat = pre-hoc grounding.
- **vs [[2402.01817-llm-modulo|LLM-Modulo]]'s critic-bank framing.** ECG-Chat's hallucination-mitigation stack is exactly the [[LLMModuloFramework]] pattern — LLM generates, external critics (GraphRAG knowledge, DDP classifier, LaTeX template) constrain — but the paper does not frame it that way; it presents the stack as a domain-engineering trick. The wiki should read it as a load-bearing **deployed LLM-Modulo instance** in clinical reporting.

## Limitations (verbatim, §VI)

> "First, due to the lack of diversity in the training dataset, the ECG features cannot be aligned with the LLM model as expected. At the same time, the dataset for instruction tuning is small and does not come from real world, which leads to bias and hallucinations in LLMs. Second, the model can still be improved in diagnosis, especially in waveforms and some rare symptoms. Finally, our model only focuses on ECG, and we also hope to combine it with the most advanced medical large language model, integrating multiple modalities such as X-Ray, EHR, etc., to provide a more comprehensive interpretation of medical records."

## What's still owed

- Whether the GraphRAG + DSPy lift survives if LoRA is removed — no ablation isolates the prompt-side contribution from the weight-side contribution.
- Whether [[GEPA]] (which DSPy now ships as a top-tier optimizer) would replace MIPRO-style optimization in the DSPy module here, and whether the prompt-shortening claim (9.2× shorter than MIPROv2) holds in a multi-turn medical dialogue setting.
- A real-world clinical validation cohort beyond the 123-pair ECG-ExpertQA — paper explicitly flags the synthetic-instruction-tuning bias.
