# Machine Learning Systems (mlsysbook Vol 1) — Ch 6: Network Architectures

## Summary

Chapter 6 of Vijay Janapa Reddi's *[[MachineLearningSystems|Introduction to Machine Learning Systems]]* (Vol 1, Harvard / mlsysbook.ai, 2026) — the longest chapter and the centerpiece of the *Build* part — reframes neural-network architecture selection as a **systems decision rather than a modeling decision**: "Selecting a neural network architecture is not a modeling decision but a *contract with physics*." The unifying concept is **[[InductiveBias|inductive bias]]** — the structural assumption each architecture bakes into its computational graph (locality for [[CNN|CNNs]], sequence for [[RNN|RNNs]], global context for [[Transformer|transformers]], dense connectivity for [[MultilayerPerceptron|MLPs]], embedding lookups for [[DLRM]]). Each family is analyzed through one consistent four-part lens — *pattern processing needs → algorithmic structure → computational mapping → system implications* — and mapped to the iron-law terms it stresses: operation count $O$ and data-movement volume $D_{\text{vol}}$ ([[IronLawOfMLSystems]]).

The chapter's organizing device is five **[[LighthouseModel|Lighthouse Models]]**, each isolating a distinct system bottleneck: **[[ResNet|ResNet-50]]** (compute / dense matrix math, ~40 FLOP/byte [[ArithmeticIntensity|arithmetic intensity]]), **[[GPT2|GPT-2 XL]]** (memory bandwidth / autoregressive decoding, ~0.5 FLOP/byte), **[[DLRM]]** (memory capacity / terabyte embedding tables), **[[MobileNetV2|MobileNet]]** (edge latency / [[DepthwiseSeparableConvolution|depthwise separable convolutions]]), and **[[KeywordSpotting|KWS]]** (always-on power / TinyML). The same arithmetic-intensity ([[RooflineModel|roofline]]) reasoning recurs: ResNet saturates ALUs while GPT-2 "starves" for bandwidth — a roughly 80× intensity gap that determines each model's "natural" hardware home.

The second half synthesizes the families: **shared building blocks** ([[GEMM|dense GEMM]], **[[SkipConnection|skip connections]]**, **normalization**, **gating**) are *portable* — born in one family but migrating across all (e.g. gating from [[LSTM|LSTMs]] reappears as [[MixtureOfExperts|MoE]] routing and [[Attention|softmax attention]]; [[BatchNormalization|BatchNorm]] from CNNs evolves to [[LayerNormalization|LayerNorm]] then [[RMSNorm]] for LLMs). Everything compiles down to a small set of **computational primitives** (matrix-multiply, sliding-window, dynamic computation) and **memory-access primitives** (sequential / strided / random) whose energy cost — DRAM access ~100×+ a MAC — drives hardware specialization ([[TensorCore|Tensor Cores]], [[SystolicArray|systolic arrays]], [[HBM]], scratchpads). The chapter closes with a step-by-step **architecture-selection framework** (a worked wildlife-camera-trap case landing on [[MobileNetV2]]) and a long **Fallacies & Pitfalls** section. Thesis: *architecture is infrastructure* — the choice signs an irreversible physical contract that determines memory footprint, latency floor, power envelope, and scaling limit, and "cannot be renegotiated through clever optimization."

## Key Claims

- **Architecture is a "contract with physics," not a modeling choice.** A CNN commits to spatially local, parallelizable computation; a transformer commits to attention whose memory grows quadratically with sequence length; a recommendation model commits to embedding tables that dominate memory. These propagate through the whole stack and are *irreversible in practice* — data pipelines, training infra, serving systems, and monitoring are all built around the architecture's format.
- **Five families, five bottlenecks (the iron-law signature table):** MLPs → memory bandwidth (dense activations); CNNs → compute throughput (high [[ArithmeticIntensity|arithmetic intensity]]); RNNs → sequential dependencies (latency-bound critical path); transformers → memory capacity $\mathcal{O}(S^2)$; DLRM → memory capacity at TB+ scale (embedding tables).
- **[[InductiveBias|Inductive bias]] reduces the data and parameters needed.** A 3×3 CNN kernel on a 224×224 image needs ~5,500× fewer parameters than the equivalent dense input connection. Bias eliminates entire hypothesis classes at *design time* (unlike regularization, which only penalizes at training time). Stronger bias is *not* always better — the [[NoFreeLunchTheorem|No Free Lunch theorem]] formalizes that a bias helping one task hurts another.
- **The learnability gap** ([[LearnabilityGap]]): the [[UniversalApproximationTheorem|Universal Approximation Theorem]] guarantees MLPs can *represent* any continuous function but gives no bounds on the network width or samples needed; required width/samples can scale as $\mathcal{O}(\exp(d_{\text{in}}))$. The MNIST case: an MLP (784→4096→4096→10) uses ~20M params for ~97–98% accuracy; a CNN uses ~420K params for ~99% — a ~47× parameter reduction *with higher* accuracy, because the CNN's locality bias matches the data.
- **MLPs move maximum data for minimum compute.** A 1024×1024 dense layer = 1,048,576 weights (~2 MB FP16). Batch-1 dense layers have arithmetic intensity ≈ 0.5 FLOP/byte (2·M·N FLOPs / 4·M·N bytes), so they are memory-bandwidth-bound unless batch sizes exceed several hundred — "fully connected layers are often the performance bottleneck in inference despite fewer total FLOPs than convolutions."
- **CNNs decouple parameter count from input resolution via [[WeightSharing|weight sharing]].** A 3×3, 64-in/64-out conv layer = ~37K params regardless of whether the image is 224×224 or 1024×1024; the equivalent FC layer ≈ 205M params (~5,500× more). Convolution is implemented on hardware via **[[Im2col|im2col]] → [[GEMM]]** (5–10× speedup leveraging mature BLAS like cuBLAS/oneMKL), trading memory (interior elements duplicated up to $K^2$×) for compute regularity.
- **[[DepthwiseSeparableConvolution|Depthwise separable convolutions]]** (Sifre; popularized by [[MobileNetV2|MobileNet]]) factor standard convolution into depthwise + pointwise (1×1) steps, cutting cost by ≈ $1/C_{\text{out}} + 1/K^2$ (≈ $1/K^2$, i.e. 8–9× for 3×3 kernels). These power both MobileNet (edge vision) and [[KeywordSpotting|KWS]] DS-CNN (TinyML, milliwatt budgets).
- **RNNs hit the "wall of time."** The recurrence $\mathbf{h}_t=\tanh(\mathbf{W}_{hh}\mathbf{h}_{t-1}+\mathbf{W}_{hx}\mathbf{x}_t)$ forces step $t$ to wait for $t-1$: a 1,000-word document = 1,000 *serial* matrix-vector multiplies. No additional hardware accelerates this critical path; parallel width is limited to batch size. RNNs are uniquely memory-*efficient* though — a fixed $\mathcal{O}(d_{\text{hidden}})$ state (e.g. 2 KB for 512-dim) regardless of sequence length, at the cost of an information bottleneck and the [[VanishingGradient|vanishing gradient]] problem.
- **[[Attention]] replaces structural constraints with learned, content-dependent routing.** Scaled dot-product attention $\text{softmax}(QK^T/\sqrt{d_k})V$ computes an $S{\times}S$ matrix giving $\mathcal{O}(1)$ information-flow depth between any two positions. [[Softmax]] is itself a systems bottleneck: it needs a full pass over all $S$ scores for the normalizer, forcing the full matrix to be materialized (or tiled, as [[FlashAttention]] does) — the root cause of quadratic memory.
- **The "quadratic wall."** BERT-style models fixed a 512-token max length as a *physics* decision: doubling 512→1024 quadruples attention-score memory; 512→4096 = 64×. A single long document would OOM the cluster, fragmenting the industry into 512-token chunks for years until $\mathcal{O}(S)$ approximations (Linformer) and IO-aware [[FlashAttention]] arrived.
- **[[Transformer|Transformers]] bifurcate by phase.** *Training* processes all tokens in parallel → compute-bound, $\mathcal{O}(S^2)$ (a 32k×32k attention matrix needs gigabytes). *Inference* is autoregressive → memory-bandwidth-bound: generating one token reloads all weights (e.g. 140 GB for a 70B model at FP16) for a single matrix-vector multiply, plus reading/writing the **[[KVCache|KV cache]]** (which grows linearly $\mathcal{O}(N_L \cdot 2 \cdot N_{\text{heads}} \cdot S \cdot d_{\text{head}})$, distinct from the $\mathcal{O}(S^2)$ training matrix).
- **Context windows exploded ~1000× in two years:** flat at 512–2K tokens 2018–2022, then GPT-4 Turbo (128K), Claude 2.1 (200K), Gemini 1.5 (1M+) — enabled by FlashAttention, sparse attention, and architectural innovation.
- **[[DLRM]] is the forgotten industrial workload.** RecSys accounts for a *majority* of AI inference cycles at Meta/Google/Amazon yet receives a fraction of academic attention. It is **memory-capacity-bound**: a 1B-user, 128-dim FP32 embedding table ≈ 512 GB; industrial models reach TB–PB. This forces **[[ModelParallelism|embedding sharding]]** across hundreds of GPUs and an **[[AllToAllCommunication|all-to-all]]** communication pattern — performance limited by *bisection bandwidth* (NVLink/InfiniBand), not FLOP/s. Embedding lookups are index-based gathers (no arithmetic) with random access that defeats caching.
- **Building blocks are portable.** [[SkipConnection|Skip connections]] (ResNet's $\mathbf{y}=\mathcal{F}(\mathbf{x})+\mathbf{x}$) create a "gradient highway" (Jacobian $\mathbf{I}+\mathcal{F}'$, eigenvalues clustered near 1) enabling 100+ layer training; a 56-layer *plain* net had worse CIFAR-10 error (~13.6%) than a 20-layer plain net (~8.8%), but a 56-layer *residual* net reached ~7.0%. Depth needs architectural support: <20 layers fine without skips, 20–100 layers require them, >100 require skips + careful normalization.
- **Normalization evolution = systems pressure.** [[BatchNormalization|BatchNorm]] cut ImageNet training time 14× but has batch-size dependency (degrades below 16, unstable below 8) and training-serving skew; [[LayerNormalization|LayerNorm]] removed batch dependency for transformers; [[RMSNorm]] dropped mean-centering, cutting per-layer normalization latency 7–64% (adopted by LLaMA/Mistral and most post-2023 LLMs).
- **The transformer is a *recombination*, not an invention:** dense GEMM (feedforward) + skip connections + normalization (LayerNorm) + gating (softmax attention; MoE routing) — only attention-specific optimizations (FlashAttention, sparse attention) are architecture-specific; GEMM tiling, mixed precision, and norm fusion transfer to every family. [[VisionTransformer|ViTs]] reuse all four blocks but need 3–5× more data/compute than CNNs to match ImageNet accuracy (weaker bias ⇄ more data, a substitution).
- **Moving data costs more than computing on it.** A FP MAC ≈ 1–5 pJ (~4.6 pJ at 45 nm, Horowitz 2014); a 32-bit DRAM fetch costs hundreds of pJ — 100×+ more. This energy law (not FLOP count) determines real efficiency and drives [[TensorCore|Tensor Cores]], [[SystolicArray|systolic arrays]] (TPU), [[HBM]] (~5× the cost of standard DRAM, the single most expensive component on a GPU), and software-managed scratchpads (FlashAttention tiles attention into scratchpad to avoid $\mathcal{O}(S^2)$ HBM traffic).
- **FLOPs ≠ speed.** MobileNet uses ~14× fewer FLOPs than ResNet-50 but can run *slower* on data-center GPUs because its low arithmetic intensity starves compute units. Architecture-hardware *alignment* determines throughput. Hardware utilization by family: MLPs 80–90% of peak, CNNs 60–75%, RNNs 30–50% (sequential), transformers 70–85% (large batch) but drops sharply at small batch.

## Key Quotes

> "Selecting a neural network architecture is not a modeling decision but a *contract with physics*." — opening thesis; the chapter's organizing claim

> "The architecture is not what the model *does* but what the hardware *must do*, and every downstream engineering decision inherits the physical contract it imposes." — on irreversibility of architecture choice

> "Architecture choice must be judged against the cost of running the model, not only the accuracy it achieves on a static benchmark." — war story: the Netflix Prize Grand Prize ensemble (BellKor's Pragmatic Chaos, 10.06% RMSE improvement, 100+ blended models) was won in 2009 but never shipped — too expensive to deploy

> "This was not a *product* decision; it was a *physics* decision." — on the BERT 512-token "quadratic wall"; doubling context quadruples attention memory

> "recommendation systems account for a majority of AI inference cycles at companies like Meta, Google, and Amazon, yet receive a fraction of the academic attention devoted to language or vision models. The reason is architectural." — on DLRM's memory-capacity bottleneck

> "the building blocks that matter most are not tied to any single architecture but solve universal problems." — on the portability of skip connections, normalization, and gating

> "*Architecture is infrastructure.* The choice between MLPs, CNNs, RNNs, transformers, and DLRM determines the physical viability of the system: its memory footprint, latency floor, power envelope, and scaling limit." — Summary

> "These commitments *cannot* be renegotiated through clever optimization—they are baked into the mathematics." — closing argument

## Contradictions

- **No direct contradictions** with sibling mlsysbook chapters or existing wiki architecture pages; this chapter *deepens and systematizes* the [[ArithmeticIntensity]] / [[RooflineModel]] / [[IronLawOfMLSystems]] framing established in [[mlsysbook-ch01-introduction]] and [[mlsysbook-ch02-ml-systems]], applying it concept-by-concept to each family.
- **Emphasis difference vs. modeling-centric sources.** Where most wiki architecture pages (e.g. [[Transformer]], [[CNN]], drawn from D2L / Hands-On-LLM / the original papers) describe architectures by what they *learn* and their accuracy, this chapter deliberately inverts the framing to what they *cost on hardware* (memory/compute/bandwidth/capacity/power). Reconcile by treating mlsysbook-ch06 as the *systems-engineering complement* to those pages, not a competing account.
- **"FLOPs do not equal speed"** explicitly pushes back on the common intuition (and some efficiency-model framing) that fewer FLOPs ⇒ faster: MobileNet's lower arithmetic intensity can make it *slower* than ResNet-50 on a data-center GPU. This is a clarification, not a conflict — already consistent with [[ArithmeticIntensity]]/[[RooflineModel]].
- **DLRM as a capacity regime "the iron law does not directly address."** The chapter notes that for DLRM neither $O$ nor $D_{\text{vol}}$ is binding — raw memory capacity is — explicitly flagging this as outside the iron law's original scope. A scoping note for [[IronLawOfMLSystems]] rather than a contradiction.
