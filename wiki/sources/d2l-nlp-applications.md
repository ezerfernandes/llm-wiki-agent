## Summary

[[AstonZhang|Zhang]], [[ZacharyLipton|Lipton]], [[MuLi|Li]] & [[AlexanderSmola|Smola]]'s seven-section *Natural Language Processing: Applications* chapter — the **downstream** companion to [[d2l-nlp-pretraining]]. Where the pretraining chapter built [[Word2Vec]] / [[GloVe]] / [[FastText]] / [[BERT]] from scratch, this chapter shows **how to apply those pretrained text representations to two representative downstream tasks**: [[SentimentAnalysis|sentiment analysis]] (single-text classification, on Stanford's [[IMDb]] review dataset, 25k train + 25k test, binary positive / negative) and [[NaturalLanguageInference|natural language inference]] (text-pair classification on [[SNLI]], 550k train + 10k test, three labels entailment / contradiction / neutral). Pedagogically, the chapter walks through **four architectural choices** for the same downstream task — RNN, CNN, attention+MLP, and fine-tuned BERT — to teach that *pretrained representation* and *downstream architecture* are orthogonal axes. Closes with a **fine-tuning BERT template** (single-sentence vs sentence-pair vs token-level via `[CLS]` reuse or per-token heads) covering sentiment classification, NLI, semantic textual similarity, part-of-speech tagging, and question answering ([[SQuAD]]).

## Key Claims

- **NLP tasks decompose into sequence-level vs token-level**: sequence-level outputs one label per sequence (single-text classification — sentiment / [[CoLA]] grammaticality; text-pair classification — [[NaturalLanguageInference|NLI]] / [[SemanticTextualSimilarity|STS]]); token-level outputs one label per token (part-of-speech tagging, named-entity recognition, [[QuestionAnswering|question answering]] span prediction).
- **Sentiment analysis = text classification**: "transforms a varying-length text sequence into a fixed-length text category." Uses Stanford's IMDb large movie review dataset (Maas et al. 2011; 25k train / 25k test, balanced positive / negative). Token-level vocabulary with `min_freq=5`, sequences truncated / padded to length 500.
- **RNN sentiment baseline (§sentiment-analysis-rnn)**: pretrained [[GloVe]]-100d embeddings (frozen) → 2-layer [[BidirectionalRNN|bidirectional]] [[LSTM]] → concatenate hidden states at initial and final time steps as the sequence representation → fully connected head with 2 outputs. Embeddings *are not updated* during training (set `requires_grad = False`).
- **textCNN sentiment classifier (§sentiment-analysis-cnn)** — Kim (2014) — applies one-dimensional CNNs to text by treating a sentence as a 1-D "image": multiple 1-D convolution kernels of different widths (3 / 4 / 5) capture local $n$-gram features, [[MaxOverTimePooling|max-over-time pooling]] (Collobert, Weston, Bottou et al. 2011) extracts the most salient activation per channel, concatenated and fed through dropout + FC head. Two embedding layers — one trainable, one frozen with GloVe — capture both task-specific and pretraining signal.
- **Multi-channel 1-D conv ≡ single-channel 2-D conv** with kernel height = input channels: structural equivalence that lets the textCNN inherit all of D2L's 2-D conv machinery from [[d2l-convolutional-neural-networks]] / [[d2l-convolutional-modern]].
- **[[NaturalLanguageInference|Natural language inference]] (§natural-language-inference-and-dataset)** decides whether a *hypothesis* can be inferred from a *premise* — three labels: **entailment** ("Two women are hugging" → "Two women are showing affection"), **contradiction** ("running the coding example" → "not sleeping"), **neutral** ("are performing for us" ↛ "are famous"). Also called *recognizing textual entailment*. Applications: information retrieval, open-domain QA, redundancy elimination.
- **[[SNLI|Stanford Natural Language Inference]] corpus** (Bowman, Angeli, Potts & Manning 2015) is the canonical NLI benchmark — 500k+ labeled English sentence pairs, balanced across the three labels in both train and test splits.
- **[[DecomposableAttention|Decomposable attention model]]** (Parikh, Täckström, Das & Uszkoreit 2016) addresses NLI **without recurrent or convolutional layers**, using only attention + MLPs and far fewer parameters — best result on SNLI at the time. Three jointly-trained steps: **(1) attend** — align tokens cross-sequence via $e_{ij} = f(\mathbf{a}_i)^\top f(\mathbf{b}_j)$ where $f$ is a shared MLP applied *separately* to each token (the **decomposition trick** — $\mathcal{O}(m+n)$ MLP calls, linear instead of quadratic) → softmax-weighted aligned representations $\boldsymbol{\beta}_i$, $\boldsymbol{\alpha}_j$; **(2) compare** — feed concatenations $[a_i, \beta_i]$, $[b_j, \alpha_j]$ through MLP $g$ to obtain per-token comparison vectors; **(3) aggregate** — sum-pool both sets and feed concatenation through MLP $h$ to a 3-way softmax. Forerunner of self-attention's "Q/K/V" computations.
- **BERT fine-tuning template (§finetuning-bert)** requires only an **extra fully-connected layer (or two)** for every downstream NLP task — single-text classification (sentiment / CoLA), text-pair classification (NLI), text-pair regression (STS), token-level tagging (POS), and span prediction (SQuAD). Pretrained BERT encoder + MLP head; output-layer parameters learned from scratch; *all other BERT parameters fine-tuned*.
- **`[CLS]` token reuse**: for sequence-level tasks, the BERT hidden state at position 0 (`[CLS]`) is fed into the head. For text-pair tasks, the input is `[CLS] sent_A [SEP] sent_B [SEP]` with segment-A / segment-B embeddings; `[CLS]` still aggregates both. Per-token tasks (POS tagging, QA) apply the same head independently to *every* token position's BERT representation.
- **Question answering ([[SQuAD]] v1.1)** (Rajpurkar, Zhang, Lopyrev & Liang 2016): given (question, passage) pack as `[CLS] Q [SEP] P [SEP]`; two independent linear heads transform each passage-token BERT vector into start-score $s_i$ and end-score $e_i$; softmax over positions yields start / end probabilities; predict the span maximizing $s_i + e_j$ subject to $i \le j$.
- **Architecture choice vs. resource budget**: when computational resources are limited, hand-crafted RNN / CNN / decomposable-attention models beat fine-tuning a 110M / 340M-parameter BERT. The chapter explicitly trades off "minimal architecture changes" (BERT) against "minimal compute" (crafted models). For the demo, D2L provides a "bert.small" variant for fine-tuning on educational hardware.
- **`SNLIBERTDataset` preprocesses pairs**: tokenize → lowercase → truncate jointly so $|p| + |h| \le \text{max\_len} - 3$ (reserving slots for `<CLS>` + 2× `<SEP>`) → `get_tokens_and_segments` builds the segment-id vector → pad to `max_len`. Encapsulates the canonical BERT input-construction recipe for sentence pairs.
- **Linear-complexity attention via decomposition**: Parikh et al.'s $f$ applies independently to each token before the dot product — a key insight that prefigured why scaled dot-product self-attention is tractable. Token-pair scoring without a quadratic MLP is the same architectural trick that makes the [[Transformer]] feasible.

## Key Quotes

> "Our focus is on *how to apply (deep) representation learning of languages to addressing natural language processing problems*. Given pretrained text representations, this chapter will explore two popular and representative downstream natural language processing tasks: sentiment analysis and natural language inference, which analyze single text and relationships of text pairs, respectively." — chapter introduction, framing the *pretrain → fine-tune* template.

> "BERT requires minimal architecture changes for a wide range of natural language processing applications. However, this benefit comes at the cost of fine-tuning a huge number of BERT parameters for the downstream applications. When space or time is limited, those crafted models based on MLPs, CNNs, RNNs, and attention are more feasible." — the central engineering trade-off of the chapter.

> "Natural language inference studies whether a *hypothesis* can be inferred from a *premise*, where both are a text sequence. In other words, natural language inference determines the logical relationship between a pair of text sequences. Such relationships usually fall into three types: *Entailment*, *Contradiction*, *Neutral*." — definition of NLI.

> "This *decomposition* trick leads to only $m + n$ applications (linear complexity) of $f$ rather than $mn$ applications (quadratic complexity)." — Parikh et al. 2016 architecture insight, structurally the same trick that makes scaled dot-product self-attention efficient.

> "During fine-tuning, the BERT model becomes part of the model for the downstream application. Parameters that are only related to pretraining loss will not be updated during fine-tuning." — explicit articulation that the `MaskLM` / `NextSentencePred` MLP heads are *staled* during fine-tuning while the encoder is fully trainable.
