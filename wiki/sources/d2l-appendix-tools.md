## Summary

[[AstonZhang|Zhang]], [[ZacharyLipton|Lipton]], [[MuLi|Li]] & [[AlexanderSmola|Smola]]'s **operational appendix** to *Dive into Deep Learning* — eight sections spanning the *tooling* layer that makes the rest of the book runnable: [[Jupyter|Jupyter Notebook]] as the primary authoring environment (with the `notedown` plugin for editing markdown-source notebooks and the ssh `-L` port-forwarding pattern for remote kernels); [[AmazonSageMaker|Amazon SageMaker]] as the **fastest path to a GPU notebook in the cloud** (`ml.p3.2xlarge` with one V100 + 8-core CPU "powerful enough for most of the book"); [[AmazonEC2|raw EC2 instances]] as the cheaper-but-more-work alternative (Ubuntu AMI → key pair → SSH → install [[CUDA]] 12.1 → [[Miniconda]] → `pip install d2l==1.0.3` → port-forward Jupyter); [[GoogleColab]] as the free-tier alternative for readers without an AWS account; a *Selecting Servers and GPUs* hardware guide for on-prem builds (power supply / chassis / cooling / [[PCIe]] lanes, with explicit beginner / 1-GPU / 2-GPU / 4-GPU / 8-GPU server recipes); a *Contributing* tutorial walking through the GitHub fork → clone → edit → pull-request flow with `%%tab` framework-tag conventions for multi-framework chapters; and the `d2l` Python package API documentation (alphabetical autodoc of every class — [[Module]] / [[DataModule]] / [[Trainer]] / [[MultiHeadAttention]] / [[TransformerEncoder]] / [[Seq2Seq]] / [[Vocab]] / [[ProgressBoard]] — and every function — `try_gpu` / `try_all_gpus` / `corr2d` / `bleu` / `plot` / `add_to_class`). This appendix is the chapter that lets a reader actually *do* the rest of the book.

## Key Claims

- **[[Jupyter]] is D2L's primary authoring + execution environment.** Every chapter is a `.ipynb` file that the reader opens with `jupyter notebook` from inside the unzipped `d2l-en/` directory. The interactive markdown-cell + code-cell + rendered-output workflow is the unit of pedagogy ("one working example, one notebook").
- **The `notedown` plugin** (`pip install d2l-notedown`) lets contributors edit notebooks in **markdown source format** directly inside Jupyter — sidestepping `.ipynb`'s "lots of auxiliary data ... confusing for Git, making reviewing contributions very difficult." Enable globally by adding `c.NotebookApp.contents_manager_class = 'notedown.NotedownContentsManager'` to `~/.jupyter/jupyter_notebook_config.py`.
- **SSH port forwarding** (`ssh myserver -L 8888:localhost:8888`) is the canonical pattern for running Jupyter on a remote GPU server while editing in a local browser. Repeated across all three cloud sections (Jupyter / AWS / SageMaker) — *the* operational primitive of cloud DL.
- **[[AmazonSageMaker|Amazon SageMaker]] is the fastest path to a GPU notebook**: console → Amazon SageMaker → Create notebook instance → choose type (`ml.p3.2xlarge` = 1× Tesla V100 + 8-core CPU, "powerful enough for most of the book") → specify the framework-specific D2L GitHub repo URL (`d2l-pytorch-sagemaker` / `d2l-en-sagemaker` / `d2l-tensorflow-sagemaker`) → SageMaker clones the entire book onto the instance → click "Open Jupyter". *"Stopping is critical to avoid being charged further"* — billed by uptime.
- **Self-managed [[AmazonEC2|EC2]] costs less than SageMaker** but requires three steps: (1) request a GPU instance type from the EC2 console (`p2.xlarge` = K80, `p3.x` = V100, `p4.x` = A100, `g4.x` = T4 inference-optimized) under a region that has them and that the account's quota permits — quota increases take "one business day to process"; (2) install [[CUDA]] 12.1 from NVIDIA's repo (`wget` → `dpkg -i` → `apt-get install cuda` → `nvidia-smi`) and append `/usr/local/cuda-12.1/bin` to `PATH` + `lib64` to `LD_LIBRARY_PATH` in `~/.bashrc`; (3) follow the standard [[d2l-installation]] runbook ([[Miniconda]] → `conda activate d2l` → `pip install d2l==1.0.3`).
- **AWS billing semantics distinguish *stopping* vs *terminating* an instance.** Stopped instances retain disk and can be restarted (billed for retained EBS); terminated instances delete all state. Best practice: snapshot via "Image → Create" before terminating so a new instance can boot from the saved AMI (with CUDA + Miniconda + d2l already installed).
- **[[GoogleColab]] is the free-tier alternative.** Each section of the book has a "Colab" button that opens it pre-loaded; if a GPU is needed, Colab is "automatically requested for connecting to a GPU instance." The simplest entry point for readers without an AWS account.
- **GPUs over CPUs by an order of magnitude** for DL training. *"In particular, compared with CPUs, GPUs are cheaper and offer higher performance, often by over an order of magnitude."* A single server supports up to 4 GPUs in a typical engineering workstation, 8 in a high-end dedicated chassis — "heat, cooling, and power requirements escalate quickly beyond what an office building can support."
- **Concrete on-prem server recipes** by GPU count: **Beginner** (cheap gaming GPU 150–200W on existing computer); **1-GPU** (4-core CPU + 32 GB DRAM + SSD + 600W PSU); **2-GPU** (4–6-core CPU + 64 GB DRAM + 1000W PSU + dual PCIe 3.0 x16 with 60mm spacing); **4-GPU** (high-clock CPU like AMD Threadripper + 128 GB DRAM + 1600–2000W PSU + 4× PCIe 3.0 x16 via PLX + reference-design GPUs + 1–2 TB NVMe SSD + RAID HDDs — *"runs loud and hot. You do not want it under your desk"*); **8-GPU** (dedicated server chassis + dual-socket server CPUs + 256 GB ECC DRAM + 10 GbE + redundant 2+1×1600W PSUs — and check the **physical form factor** because consumer RTX 2080 won't physically fit in a Tesla V100-shaped chassis).
- **GPU selection: NVIDIA dominates because of [[CUDA]] support** for DL frameworks. Two product lines: consumer (GTX / RTX, fan-cooled, no ECC) and enterprise (Tesla, passive forced cooling, ECC memory, ~10× the cost). GPU performance ≈ three parameters: (1) **compute power** (32-bit FLOPs primary; FP16 mainstream; INT8 for inference; INT4 on latest Turing); (2) **memory size** ($\geq 4$ GB minimum, $\geq 8$ GB strongly preferred; HBM2 > GDDR6); (3) **memory bandwidth** (wide buses on GDDR6). Most users only need to look at compute power. Within each generation price ≈ proportional to GFLOPs; the GTX 1000 series is ~2× more cost-effective than the 900 series; RTX adds Tensor Cores at the price of disproportionate energy draw.
- **The `d2l` Python package** is the alphabetically-autodocumented API (`d2l.torch` / `d2l.mxnet` / `d2l.tensorflow` modules) shipping every reusable class introduced across the book — [[Module]] / [[DataModule]] / [[Trainer]] / [[HyperParameters]] / [[ProgressBoard]] (OO scaffold from [[d2l-linear-regression]]); [[LinearRegression]] / [[LinearRegressionScratch]] / [[SoftmaxRegression]] / [[Classifier]] / [[LeNet]] (early chapters); [[RNN]] / [[RNNScratch]] / [[GRU]] / [[RNNLM]] / [[Seq2Seq]] / [[Seq2SeqEncoder]] / [[Encoder]] / [[Decoder]] / [[EncoderDecoder]] / [[AttentionDecoder]] (sequence chapters); [[AdditiveAttention]] / [[DotProductAttention]] / [[MultiHeadAttention]] / [[PositionalEncoding]] / [[PositionWiseFFN]] / [[AddNorm]] / [[Residual]] / [[ResNeXtBlock]] / [[TransformerEncoder]] / [[TransformerEncoderBlock]] (attention + Transformer chapters); [[FashionMNIST]] / [[SyntheticRegressionData]] / [[TimeMachine]] / [[MTFraEng]] / [[Vocab]] (data + tokenization); [[SGD]] (optimizer). Plus function helpers `try_gpu` / `try_all_gpus` / `cpu` / `gpu` / `num_gpus` (device selection), `corr2d` (convolution), `bleu` (MT eval), `masked_softmax` / `init_seq2seq` / `init_cnn` (init helpers), `plot` / `set_axes` / `set_figsize` / `show_heatmaps` / `show_list_len_pair_hist` / `use_svg_display` (plotting), and `add_to_class` / `check_shape` / `check_len` (the `#@save`-pattern decorator).
- **Contributing flow**: minor changes → click "Edit this file" on GitHub, type fix, "Propose file change", "Create pull request". Major changes → fork the repo on GitHub → `git clone https://github.com/USER/d2l-en.git` → edit markdown source files (`.md`, **not** `.ipynb`) → `git add` / `git commit -m "..."` / `git push` → "New pull request" on GitHub. Multi-framework code blocks marked with `%%tab pytorch` / `%%tab tensorflow` / `%%tab mxnet` / `%%tab all`. CI runs every PR. *"Try not to submit huge pull requests since this makes them hard to understand and incorporate. Better send several smaller ones."*
