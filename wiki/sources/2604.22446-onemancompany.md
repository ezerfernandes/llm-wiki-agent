## Summary
Yu, Fu, He et al. (Huawei Noah's Ark Lab + UCL + U Liverpool) introduce **OneManCompany (OMC)**, a framework that adds an explicit **organisational layer** above multi-agent systems. OMC packages an agent identity (role, prompts, skills, tools, working principles) as a portable **Talent**; a **Container** is the heterogeneous runtime (LangGraph, Claude Code, script processes) that hosts it; together they form an **Employee** with managed lifecycle (hiring → evaluation → offboarding). A community-driven **Talent Market** supplies verified agents on demand. Project execution is modelled as an **Explore-Execute-Review (E2R) tree search** over organisational strategies, with DAG-based AND-tree task decomposition and a finite state machine providing formal guarantees on termination, deadlock freedom, and crash recovery. On PRDBench, OMC reaches **84.67% success (+15.48 pp over SOTA)**.

## Key Claims
- **The missing organisational layer.** Skills answer "what can an agent do?"; multi-agent systems answer "how do agents interact?"; AI organisations answer "how should a workforce be structured and managed to achieve complex goals?"
- **AI Organisation definition.** Self-governing system of heterogeneous agents with structured coordination, managed lifecycles, and experience-driven evolution.
- **Talent–Container split.** Decouples who an agent *is* from where it *runs*; six typed organisational interfaces mediate all agent-platform interaction, enabling cross-runtime interoperability.
- **Talent Market.** Community-driven supply side; verified agent implementations recruited on demand and provisioned through an automated hiring pipeline — mirrors HR policy plus external specialist labour market.
- **E2R tree search with DAG dependencies.** Top-down decomposition into accountable units; bottom-up aggregation drives systematic review and refinement; formal termination + deadlock-freedom guarantees.
- **Two-level evolution.** Individual-level (agents refine working principles via task feedback) and organisation-level (editable workflow SOPs and company-culture rules persist across projects).
- **Empirical.** PRDBench 84.67% (vs prior SOTA 69.19%); cross-domain case studies show generality (game development, art / sound, etc.).
- **Critique of existing frameworks.** CrewAI / AutoGen / Paperclip either hardcode team structure (brittle to novel projects) or let agents negotiate freely (no convergence guarantees); roles are descriptive prompts, not executable contracts; self-improvement is session-bound.

## Key Quotes
> "Skills are capability-level abstractions; multi-agent systems are interaction-level abstractions; an AI organisation is an organisation-level abstraction."
> "The team is fixed before the project starts."
> "How can AI agent workforces be automatically organised, coordinated, and evolved to solve open-ended tasks across domains?"

## Contradictions
- Frontal disagreement with the "let coordination emerge" lineage of [[2512.04388-conductor]] (RL-learned coordination) and the "collapse it into one model" position of [[2605.02396-heavyskill]]. Aligned with [[2605.03310-coordination-architectural-layer]] in elevating coordination to a separable layer, but goes further: the layer here is not just an architectural seam but an *organisational* one with HR-style lifecycle, market-based recruitment, and persistent SOP/culture. The Talent-Market trust assumption interacts with [[2605.00424-skills-as-verifiable-artifacts|Metere]]: a "verified" Talent imported from a community marketplace is precisely the supply-chain attack surface that paper warns about.
