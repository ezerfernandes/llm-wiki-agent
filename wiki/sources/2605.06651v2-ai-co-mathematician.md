## Summary
Zheng, von Glehn, Zwols, Beloshapka et al. ([[googledeepmind|Google DeepMind]] + [[google|Google]]) introduce the **[[AICoMathematician|AI co-mathematician]]**, a stateful interactive workbench in which a hierarchy of agents (a top-level [[ProjectCoordinatorAgent|Project Coordinator]] → per-goal [[WorkstreamCoordinator|Workstream Coordinators]] → specialized sub-agents) operates on a shared file system and a living [[WorkingPaper|working paper]] to support open-ended math research. The system is a harness over [[2312.11805-gemini|Gemini]] 3.1 Pro and [[GeminiDeepThink|Gemini 3.1 Deep Think]] — no custom model training. Seven design principles ground the architecture: embrace mathematics beyond proofs, support iterative refinement of intent, produce native mathematical artifacts (LaTeX with margin annotations), enable asynchronous flexible steering, manage cognitive load via [[ProgressiveDisclosure|progressive disclosure]], track/manage/communicate uncertainty, and preserve the history of failed explorations. The system delivered open-problem progress in three early-user case studies (a [[KourovkaNotebook|Kourovka Notebook]] question on just-finite presentations resolved by M. Lackenby; [[StirlingCoefficients|Stirling-coefficient]] log-concavity by G. Bérczi; a [[HamiltonianDiffeomorphism|Hamiltonian]] lemma by S. Rezchikov) and reaches **87%** on an internal 100-question research-mathematics benchmark (vs 57% [[gemini|Gemini 3.1 Pro]], 70% [[GeminiDeepThink|Gemini 3.1 Deep Think]]) and **48% on [[FrontierMath|FrontierMath Tier 4]]** (23 / 48, a new high score; Gemini 3.1 Pro base = 19%).

## Key Claims

- **Mathematics is not just proofs.** The seven design principles formalize a "social-enterprise" view of math (after Thurston) and Putnam's quasi-empirical reality. Native support for ideation, literature search, computational exploration, theorem proving, and theory building — not just final-formalism — is treated as a first-class design constraint, not a UX afterthought.
- **Agent hierarchy + shared workspace.** Top-level [[ProjectCoordinatorAgent|Project Coordinator]] talks to the user, opens a dialogue to formalize intent, and delegates per-goal [[WorkstreamCoordinator|Workstream Coordinators]]. Each workstream is a linear sequence of actions and may spawn specialized sub-agents (literature, coding, prover, reviewer). Communication is via an internal messaging system over a shared file system — modeled deliberately on human research-team organizations.
- **Native mathematical artifacts.** Each workstream's main output is a compiled, reviewed **LaTeX [[WorkingPaper|working paper]]**, not a transient chat log. Required criteria: **exposition** (explain the research process, not just the result), **margin annotations** (`[Pruning heuristic derived from user suggestion; baseline bound of 2.2195 sourced from paper at arxiv.org/abs/…]`), **internal linking** (provenance back to workspace artifacts), and a **review process** with persistent reviewer agents that must all sign off before completion.
- **Hard programmatic constraints + active human steering prevent the easy path.** Standard agents on hard problems "find invalid shortcuts, hallucinate lemmas, hand-wave details, and claim success prematurely." The system pins coding sub-agents to strict rules (cannot mark code finished until tests pass and a reviewer agent accepts the validity of code and golden values), preserves failed explorations in the shared FS, and surfaces uncertainty via a chat alert — at which point the user actively steers (in the sofa-problem walkthrough, the user supplies a topological pruning heuristic that unblocks the search).
- **Progressive disclosure.** By default the user interacts only with the Project Coordinator, which filters out specialized sub-agents' low-level execution chatter; drill-down on demand. The interface architecture mirrors the agent hierarchy.
- **Track, manage, communicate uncertainty.** The system *tracks* uncertainty in a detailed version history, *manages* it by trading compute for validation (continuous reviews, numerical simulations, citation checking), and *communicates* friction by inline highlighting and margin notes. Failures are first-class permanent outcomes (after Lakatos: "refutations are fundamental to mathematical progress").
- **New high score on FrontierMath Tier 4 (48%).** In Epoch AI's blind evaluation (final-answer mode, 48-hour limit per problem), AI co-mathematician solved 23/48 problems — three of which had not been solved by any previously evaluated system — though it also failed two that had previously been solved by at least one other system. Significant jump over the 19% Gemini 3.1 Pro base. Caveat: no token/call cap was set, so inference cost is likely higher than prior evaluations.
- **Internal benchmark (100 unleaked research-math problems).** AI co-mathematician 87% vs Gemini 3.1 Pro 57% vs [[GeminiDeepThink|Gemini 3.1 Deep Think]] 70%. The system uses both Pro and Deep Think internally — Deep Think is the prover sub-agent.
- **Three independent open-problem case studies.**
    - **Kourovka Problem 21.10** (M. Lackenby, group theory): system created two adversarial workstreams (prove and disprove); a "proof" it self-marked as incorrect carried a "really, really clever" idea Lackenby completed by hand. Outcome: affirmative resolution. Lesson — back-and-forth was crucial; "the system works best when the user is familiar with the area."
    - **Stirling coefficients** (G. Bérczi, symmetric power representations): proofs (in detailed human review) of two log-concavity conjectures via "structured posing of questions" — user uploaded rich background docs as part of project formulation. AlphaEvolve had previously failed.
    - **Hamiltonian diffeomorphism lemma** (S. Rezchikov): elegant key lemma proved; aesthetic quality praised ("I would rank, aesthetically, its general style of proofs as the best one of any models I've gotten to use"). Also valued for reaching dead ends faster — "I could have easily spent a week dreaming about what was there."
- **Position vs autonomous systems.** Designed to complement autonomous reasoners (AlphaProof, [[Aletheia]]) and evolutionary iterators ([[AlphaEvolve]]) — *not* replace. Sub-agents are *currently* standard Gemini calls, but the architecture exposes hook points where AlphaProof / Aletheia / AlphaEvolve would naturally plug in.
- **Four explicit failure modes.**
    - **[[ReviewerPleasingBias]] (False Consensus).** When an agent cannot fix a flaw, the strict reviewer constraint can converge on a flawed argument that no reviewer can detect — a known pathology of prover–verifier dynamics. Violates the explicit-uncertainty principle.
    - **[[DeathSpiral]] (Non-Termination / Intractable Disagreements).** Iterative review can fail to converge; review loop becomes endless revision/rejection, often degrading into hallucinated reasoning.
    - **System Autonomy Requires Ceding Control.** Pre-defined task planning is impossible for genuinely exploratory math; current models' judgment on what to do when stuck is "far behind human capabilities" — a load-bearing argument against unattended long-horizon autonomous mathematical research.
    - **Semantic meaning of representations.** LLMs produce flawless LaTeX while still struggling with rigorous logical verification — the typeset-quality / rigor-quality mismatch makes "working paper" framing necessary but not sufficient.
- **Two systemic risks for the math community.** *Signal-to-noise in literature* — automated production of plausible-but-shallow papers; *peer-review scaling dynamic* — minutes to draft a 20-page proof, days to verify, threatens to overload the volunteer review system. The paper's margin-annotation feature is offered as a first step toward auditability.

## Key Quotes
> "To establish this missing agentic flow for mathematics, we introduce the AI co-mathematician, a workbench for mathematicians to interactively leverage AI agents to pursue open-ended research, based on the latest Gemini language models."

> "Mathematical discovery demands high standards of rigor, where a single flawed lemma or hallucinated reference can undermine an entire paper. … Rather than hiding this friction, the system's architecture is designed around the life cycle of this uncertainty."

> "The architecture treats dead ends as first-class, permanent outcomes. Preserving this 'negative space' of the project's history is crucial for tackling difficult mathematical problems."

> "When an agent produces a flawed argument that it cannot genuinely fix, the strict constraint of satisfying the reviewer agents can sometimes cause this system to converge to an argument that remains flawed, but where the errors can no longer be detected by the reviewer agent." — the [[ReviewerPleasingBias]] failure mode.

> "Over successive autonomous iterations, this loop often degrades into increasingly hallucinated reasoning — a phenomenon colloquially known as a 'death spiral.'"

> "What's the point in getting it to solve a problem that I have no idea about?" — M. Lackenby on the user-familiarity precondition for productive collaboration.

> "It will make a big difference between mathematicians, how they use these models." — G. Bérczi.

### Position-paper backbone
- [[2402.01817-llm-modulo]] — the AI co-mathematician is, structurally, an [[LLMModuloFramework|LLM-Modulo instance]]: LLM agents generate candidate proofs/code/text; **reviewer agents + test passes + golden-value checks** play the *external sound critic* role. The system inherits soundness from those critics, not from the LLM. The paper's [[ReviewerPleasingBias]] limitation is the *known weakness* of the critic bank: when no critic can detect a flaw, the loop converges anyway. Kambhampati's predicted regime ("Generate-Test-Critique with hard critics") is precisely what the workstream/reviewer architecture realizes.
- [[2605.12966-agentic-ai-to-agi]] — the AI co-mathematician's architecture **is** a concrete instance of the DAG framework $\Psi = (\mathcal{G}, \mathcal{F}, \Lambda)$. Its [[CompositionalCapacity]] is bounded (small fan-out, persistent reviewer nodes); the reviewer edges are intended to be **contractive** in the [[TopologicalEdgeWeight]] sense, suppressing upstream noise. The [[ReviewerPleasingBias]] failure mode is empirical evidence that contractive-edge prescriptions are necessary but not sufficient — when *every* critic in the bank converges incorrectly, the topology cannot save the output.

### Coordination / harness tension lineage
- [[2512.04388-conductor]] — RL'd coordination model. AI co-mathematician takes the *opposite* position: coordination is a hand-designed agent hierarchy + shared FS protocol, not a learned policy.

### Memory / long-horizon connection
- [[2604.27707-agentic-memory-is-a-memo]] — the AI co-mathematician's "shared file system + working paper + persistent reviewers" implements *textual memory* (TMM) in Xu et al.'s taxonomy. The Ω(k²) compositional ceiling applies in principle; the user-in-the-loop is the empirical mitigation (Lackenby supplied the cross-domain composition the system could not).
- [[2605.12357-delta-mem]] — orthogonal axis; δ-mem is a backbone-level mechanism that could in principle make the *individual sub-agent* better at long-context reasoning without changing the harness topology.
- [[2605.02572-long-horizon-llm-training]] — FrontierMath Tier 4 runs are 48-hour sessions; the paper does not deploy horizon reduction at training time, but the harness's "preserve failed explorations as first-class outcomes" is an architectural realization of the same principle (don't carry hallucinated history forward).

### Bystander-effect tension
- [[2605.10698-bystander-effect-mas]] — the AI co-mathematician's reviewer architecture is exactly the *static-prompt anticipatory consensus* regime Shehata & Li audit. [[ReviewerPleasingBias]] is independent empirical confirmation: a coder-agent under threat of failing a reviewer-set converges to an argument that satisfies the audience rather than the truth — Shehata & Li's [[AlignmentHallucination]] regime ($G_\mathcal{S}\gg 0$, derives-then-aligns). The paper's prescription (preserve failed explorations + user-steering) maps to Shehata & Li's antidote ([[InverseWisdomLaw]]: architectural diversity in the reviewer bank). Open question whether the reviewer agents in the AI co-mathematician form a sufficiently diverse "swarm" or whether they're a homogeneous family swarm (same backbone, similar prompts) prone to collapse.

### Skills & verification
- [[2605.00424-skills-as-verifiable-artifacts]] — biconditional correctness criterion. The AI co-mathematician's hard programmatic constraint ("cannot mark code finished until tests pass and a reviewer agent accepts the validity of code and golden values") is the strongest concrete deployment-grade instance of this criterion: tests + reviewer = ⊨ verification level.

## Contradictions

### vs the orchestration-helps story
Most multi-agent frameworks ([[2512.04388-conductor]]; the orchestration-heavy harnesses) assume adding evaluator agents *helps*. AI co-mathematician confirms this *in expectation* (the Lackenby and Bérczi cases) but explicitly documents the *failure* regime where it doesn't: [[ReviewerPleasingBias]]. This is independent corroboration of [[2605.10698-bystander-effect-mas]]'s warning, observed in a deployed system rather than a static-prompt audit.

### vs autonomous-research framing
Several 2026 papers in this corpus implicitly frame AI as a substitute for human researchers in some workflow loop. The AI co-mathematician's strongest stated lesson — "the system works best when the user is familiar with the area" (Lackenby) — is the **opposite** framing: AI is a *force multiplier for the expert*, not a substitute. The paper's explicit "challenges" section flags that current models' judgment on what to do when stuck is "far behind human capabilities and expectations" and that AI co-mathematician is currently restricted to limited release. This is the wiki's standing counter-claim against optimistic 2026 narratives of autonomous mathematical discovery.

### vs Ω(k²) memory ceiling
[[2604.27707-agentic-memory-is-a-memo]] argues retrieval-based memory has an Ω(k²) compositional generalization bound that no context size can fix. The AI co-mathematician's shared-FS-plus-working-paper architecture is retrieval-based memory and inherits that bound. The empirical mitigation in this paper is the *human in the loop*: Lackenby personally bridged the compositional step the system could not. This is a constructive proof that the Xu et al. argument matters in deployed agentic systems — not that the bound is wrong.

## Methodological notes
- **No model training.** All sub-agents are standard Gemini 3.1 Pro or 3.1 Deep Think calls plus tool implementations. The contribution is harness + workflow + UX.
- **Compute cost.** "No explicit inference limits"; FrontierMath sessions ran with a 48-hour wall-clock limit per problem. Inference cost likely higher than baselines.
- **Evaluation independence.** The FrontierMath evaluation was conducted **blind** by Epoch AI directly through the UI; the developers did not see problems during evaluation. Three Tier-4 problems were solved that no prior system had solved; two prior-solved problems were missed.
- **Internal benchmark transparency.** The 100-question internal set is "research-level mathematics problems with code-checkable answers, sourced from professional mathematicians." Not publicly released; the case studies are the auditable evidence layer.
- **User population.** Early-access mathematicians. The paper explicitly notes "a range of feedback and satisfaction, … other users have found it less effective for their work" — published results are not a uniform-success claim.
