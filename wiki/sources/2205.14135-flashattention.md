## Summary
Dao, Fu, Ermon, Rudra & Ré (Stanford + Univ. at Buffalo SUNY) introduce **FlashAttention**, an **IO-aware exact attention algorithm** that uses **tiling** to avoid materializing the N×N attention matrix in slow GPU high-bandwidth memory (HBM) and **recomputation** to skip storing it for the backward pass. The single fused CUDA kernel computes the same softmax(QKᵀ)V as standard attention but requires Θ(N²d²M⁻¹) HBM accesses (where d is head dim, M is SRAM size) versus Θ(Nd+N²) for the standard implementation — many times fewer for typical d∈[64,128] and M≈100KB. End-to-end wins: BERT-large 15% faster than the MLPerf 1.1 training record, GPT-2 3× faster than HuggingFace, LRA 2.4× faster, and the **first Transformer to beat chance on Path-X (16K) at 61.4%** and Path-256 (64K, block-sparse variant) at 63.1%. FlashAttention is a load-bearing systems result for every later long-context Transformer in this wiki — the kernel optimization that makes the [[Transformer]] cheap enough to scale context length without trading off model quality.

## Key Claims
- **The bottleneck is memory access, not FLOPs.** Standard attention is memory-bound: writing/reading the N×N matrices S=QKᵀ and P=softmax(S) to/from HBM dominates runtime. The right principle for attention algorithms is **IO-awareness** — minimize HBM ↔ SRAM traffic, not FLOP count.
- **Tiling computes softmax block-by-block.** By keeping running statistics (m, ℓ) per block — the running max and the running sum of exp(x−m) — softmax can be incrementally rescaled across blocks without ever materializing the full N×N matrix. Block sizes are chosen so K, V, Q tiles fit in on-chip SRAM (B_c = ⌈M/4d⌉, B_r = min(⌈M/4d⌉, d)).
- **Recomputation replaces storing P.** Standard attention writes S, P ∈ ℝ^{N×N} to HBM during the forward pass for use in the backward. FlashAttention stores only (m, ℓ, O) — Θ(N) — and recomputes S, P on-chip from blocks of Q, K, V during the backward. More FLOPs, but fewer HBM accesses → faster backward.
- **IO complexity bound.** FlashAttention requires Θ(N²d²M⁻¹) HBM accesses for both forward and backward, vs. Θ(Nd+N²) for the standard implementation. For typical d (64–128) and SRAM size M (~100 KB), d²/M is many times smaller than 1.
- **Lower bound: optimal up to constants.** Proposition 3 — no exact attention algorithm can asymptotically improve on Θ(N²d²M⁻¹) HBM accesses for all M ∈ [d, Nd]. FlashAttention is IO-optimal in this regime.
- **Kernel fusion.** All forward-pass ops (matmul, mask, softmax, dropout, matmul) live in a single CUDA kernel — input loaded once from HBM, all intermediates kept in SRAM, only output written back. Standard PyTorch attention is many separate kernels each touching HBM.
- **Block-sparse extension.** A block-sparsity mask reduces IO by exactly the sparsity ratio s: Θ(Nd + N²d²M⁻¹·s) HBM accesses. Scales to 64K sequence length; faster than every approximate-attention baseline tested.
- **Quality is unchanged.** FlashAttention computes attention *exactly*, so it matches the same training curves as standard attention (same perplexity, same final accuracy) — speedup is pure systems, not quality/compute trade-off.
- **Quality from longer context.** The speed dividend buys context length: GPT-2 with 4K context via FlashAttention is still 30% faster than Megatron at 1K context, and reaches 0.7 better perplexity. Long-document classification lifts 6.4 F1 points on MIMIC-III / ECtHR.

## Key Quotes
> "We argue that a missing principle is making attention algorithms IO-aware — accounting for reads and writes between levels of GPU memory."

> "We apply two well-established techniques to address these challenges. (i) We restructure the attention computation to split the input into blocks and make several passes over input blocks, thus incrementally performing the softmax reduction (also known as tiling). (ii) We store the softmax normalization factor from the forward pass to quickly recompute attention on-chip in the backward pass, which is faster than the standard approach of reading the intermediate attention matrix from HBM."

> "Even with the increased FLOPs due to recomputation, our algorithm both runs faster (up to 7.6× on GPT-2) and uses less memory — linear in sequence length — than standard attention, thanks to the massively reduced amount of HBM access."

> "We prove a lower-bound: one cannot asymptotically improve on the number of HBM accesses for all values of M (the SRAM size) when computing exact attention."

## Algorithmic Reference

**Forward (Algorithm 1):** Given Q, K, V ∈ ℝ^{N×d} in HBM, on-chip SRAM of size M.
1. Set B_c = ⌈M/4d⌉, B_r = min(⌈M/4d⌉, d). Initialize O = 0, ℓ = 0, m = −∞ in HBM.
2. Divide Q into T_r = ⌈N/B_r⌉ row blocks; K, V into T_c = ⌈N/B_c⌉ column blocks.
3. Outer loop over K, V blocks (j=1..T_c). Inner loop over Q blocks (i=1..T_r).
4. On-chip: S_ij = Q_i K_jᵀ. Compute block max m̃_ij, P̃_ij = exp(S_ij − m̃_ij), ℓ̃_ij = rowsum(P̃_ij).
5. Update running stats: m_i^new = max(m_i, m̃_ij), ℓ_i^new = e^{m_i − m_i^new}·ℓ_i + e^{m̃_ij − m_i^new}·ℓ̃_ij.
6. Rescale and accumulate output: O_i ← diag(ℓ_i^new)⁻¹ · (diag(ℓ_i) e^{m_i − m_i^new} O_i + e^{m̃_ij − m_i^new} P̃_ij V_j). Write O_i, ℓ_i, m_i to HBM.

**Backward** (Appendix B): On-chip recomputation of S, P from Q, K, V blocks plus saved (m, ℓ). Same Θ(N²d²M⁻¹) HBM-access bound.

## Contradictions
None with current wiki content. FlashAttention is **exact** — it computes the same output as standard attention to floating-point tolerance — so it does not conflict with any architectural or accuracy claim made in earlier papers ([[1409.3215-seq2seq]], [[1706.03762-attention-is-all-you-need]], [[1810.04805-bert]]). It refines those papers' default attention implementation, not their definitions.

The paper does push back against a common assumption from the **approximate attention** literature (Linformer, Performer, Reformer, etc.): that quadratic attention is structurally too expensive and must be approximated. FlashAttention shows that for most practical sequence lengths exact attention is faster than approximation once IO is accounted for. This is a tension with — not a contradiction of — those alternative architectures.
