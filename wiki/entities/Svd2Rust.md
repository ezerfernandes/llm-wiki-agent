# svd2rust

Code-generation tool — `crates.io/crates/svd2rust` — that consumes a chip vendor's [[SVDFile|CMSIS-SVD XML file]] and emits a fully typed Rust [[PeripheralAccessCrate|Peripheral Access Crate]] (PAC) for that specific microcontroller part number. Maintained by the [[RustEmbeddedWorkingGroup]].

The generated PAC exposes each register through the closure idiom that defines the embedded-Rust register-access style ([[rust-embedded-book-start-registers]]):

- `reg.read()` → typed `R` struct with sub-field accessors.
- `reg.write(|w| …)` → closure on `W` struct; unset fields revert to SVD-declared defaults.
- `reg.modify(|r, w| …)` → safe read-modify-write.
- Sub-field setters that the SVD does not constrain are marked `unsafe`.

Every chip-specific PAC in the ecosystem — [[Tm4c123xCrate|`tm4c123x`]], `stm32f30x`, `nrf52840-pac`, `atsamd21j`, … — is auto-generated by `svd2rust`. This is the **mechanism** by which the embedded-Rust ecosystem maintains uniform register-access ergonomics across hundreds of chip families.
