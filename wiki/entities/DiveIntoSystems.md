# Dive into Systems

**Dive into Systems** is a free, openly available undergraduate computer-systems textbook by [[SuzanneJMatthews]] ([[UnitedStatesMilitaryAcademy|West Point]]), [[TiaNewhall]] ([[SwarthmoreCollege]]) and [[KevinCWebb]] ([[SwarthmoreCollege]]). It introduces [[ComputerSystem|computer systems]] from C programs down through binary representation, [[CPU]] microarchitecture, the [[MemoryHierarchy]], the [[OperatingSystem|OS]] abstraction layer, and multicore [[ParallelComputing|parallel programming]].

The book is hosted at [diveintosystems.org](https://diveintosystems.org) and is targeted at CS students who have some Java / Python experience but no prior systems background. It is explicitly an **active-reading** textbook — readers are expected to type and run the C code examples rather than skim.

## Authors

- [[SuzanneJMatthews]] — [[UnitedStatesMilitaryAcademy|U.S. Military Academy at West Point]].
- [[TiaNewhall]] — [[SwarthmoreCollege]].
- [[KevinCWebb]] — [[SwarthmoreCollege]].

## Pedagogical stance (from [[dis-0-introduction|Ch 0]])

- A [[ComputerSystem|computer system]] = [[ComputerHardware|hardware]] + [[OperatingSystem|OS]], general-purpose and reprogrammable.
- Calculators and bare microcontrollers are **not** computer systems by this definition.
- Systems knowledge drives performance: [[MemoryHierarchy|memory hierarchy]], [[BinaryRepresentation|binary representation]], and OS [[Abstraction|abstractions]] are the levers.
- Modern hardware trends toward miniaturization and parallelism: [[MulticoreProcessor|multicore]] is the default; [[SystemOnAChip|SoCs]] and [[SingleBoardComputer|single-board computers]] proliferate.

- [[dis-13-3-virtual-memory]] — Chapter 13.3 *Virtual Memory* — **third leaf** of Ch 13 *The Operating System*; codifies **[[VirtualMemory|virtual memory]]** as *"an abstraction that gives each process its own private, logical address space in which its instructions and data are stored"*. Splits memory addresses into **[[VirtualAddress|virtual]]** (process view) vs **[[PhysicalAddress|physical]]** (RAM); divides each [[AddressSpace|address space]] into fixed-size **[[Page|pages]]** (commonly 4 KB) and physical RAM into same-size **frames**. The **[[PageTable|page table]]** records per-process virtual-to-physical mappings consulted on every memory access by the [[MMU]] via the **PTBR**; each [[PageTable|PTE]] carries a frame number + **valid bit** + **dirty bit**. When `valid == 0` the access raises a **[[PageFault|page fault]]** — the OS reads the missing [[Page|page]] from the [[SwapFile|swap area]] into a free frame and restarts the instruction. **[[DemandPaging|Demand paging]]** lets processes run with only the working set resident; RAM acts as a cache for disk. The **[[TLB|Translation Lookaside Buffer]]** caches recent (page → frame) mappings so most accesses cost one RAM read instead of two. Closes with **[[LeastRecentlyUsed|LRU]]** page replacement + dirty-bit write-back as the eviction discipline and the **PTBR-update on [[ContextSwitch|context switch]]** as the hardware-enforced process-isolation mechanism. **120th ingested DIS chapter.** Mints **8 new concept pages** ([[VirtualAddress]], [[PhysicalAddress]], [[PageTable]], [[Page]], [[Paging]], [[PageFault]], [[SwapFile]], [[DemandPaging]]), **promotes [[TLB]] to a short-name canonical anchor** (sibling of the long-form [[TranslationLookasideBuffer]] page), and **extends [[VirtualMemory]] in place** from the [[parproc-appA-systems-issues|ParProc App A]] stub into the OS-textbook treatment.

- [[dis-11-3-locality]] — Chapter 11.3 *Locality* — **third leaf of Ch 11 *Memory Hierarchy***; pivots from [[dis-11-2-storage-devices|Ch 11.2]]'s storage-device taxonomy into the **empirical program-behavior property** that makes the entire [[MemoryHierarchy|memory hierarchy]] workable. Codifies the **two-axis [[LocalityOfReference|locality]] taxonomy** — *"the two basic forms of locality are temporal locality and spatial locality"* — and frames locality as the system-designer's exploit (move frequently-accessed data to fast storage, leave the rest in slow storage) that produces *"the illusion of having massive fast memory"*. - [[dis-4-2-conversion]] — Chapter 4.2 *Converting Between Bases* — the **mechanics companion** to [[dis-4-1-bases|Ch 4.1]] that turns the positional-notation framework $\sum d_i \cdot B^i$ into concrete [[BaseConversion|conversion algorithms]]. Codifies **four routes**: (1) **base-$B$ → decimal** by direct place-value sum evaluation (`0b110100110 = 422`, `0x9F = 159`); (2) **decimal → base-$B$ via powers-of-target-base** subtraction, walking from the largest power that fits down to $B^0$ ($9742 \to$ `0x260E` via $4096 \cdot 2 + 256 \cdot 6 + 16 \cdot 0 + 1 \cdot 14$); (3) **decimal → base-$B$ via [[RepeatedDivisionMethod|repeated division]]** — divide by $B$, record remainders, read **bottom-up** until quotient hits zero; for $B = 2$ this simplifies to *"if the decimal value is even, the next bit should be a zero; if it's odd, the next bit should be a one"* ($422 \to 211 \to 105 \to 52 \to 26 \to 13 \to 6 \to 3 \to 1 \to 0$ produces `0b110100110`); (4) **[[BinaryHexConversion|binary ↔ hex]] per-nibble table lookup** — because $16 = 2^4$, every hex digit corresponds to exactly four bits; partition binary into groups of four **from the right** with leading-zero padding, table-lookup each nibble (`0xB491 ↔ 1011 0100 1001 0001`). Octal analog uses 3-bit groups ($8 = 2^3$).
